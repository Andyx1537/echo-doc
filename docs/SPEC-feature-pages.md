## 0. 研究方法（我们怎么调研）

1. **按"功能"而非"产品"拆解**：把每个标准页面(发现/搜索/详情/个人页/消息/发布)拿成熟产品的**成熟交互范式**逐一拆开，提炼"一个完整的该页由哪些组件 + 交互 + 空态 + 边界组成"。
2. **对标但不照抄**（守 Moat 文档红线）：**借的是"完整度与被验证的交互模式"，不是某个产品的皮肤与身份**。运营明确反对"复古皮肤当全部价值"——我们把标准页做透，但基调、文案、视觉仍是 Echo 自己的(安静/克制/暖)。
3. **每页设"完整度清单"**：任何页面上线前必须逐条过清单(见 §2)，缺项即"未做透"，不允许当成品交付。
4. **gap 审计 → 逐页补齐**：对现有原型逐页打分(完整/部分/壳/缺)，排优先级补(见 §3)。

## 附录 A · 搜索页「8-9 成目标规格」（首个 产品+QA 联合确认样板）

> 这就是"要什么样子"的高保真目标。开发照此实现，不自由发挥；QA 按此逐条验收。视觉沿用 Echo 现有基调（暖、静、低饱和、圆角、留白），**不新造风格**。

> **v2 · 2026-08-04**：已并入 QA 首轮评审(`qa/QA-REVIEW-search-target-20260804.md`)的 **必补 9 项 + 建议 7 项**，PM 逐条拍板；下述数值/去向/信封/交互均已钉死，达"开发照做即可"门槛，待 QA 复签。

### A.1 进入与容器
- 广场顶部搜索栏**改为可点按钮**；点击 → **全屏搜索页从下往上滑入**（**定死此一种，不做整页切换**），**输入框自动聚焦**、拉起键盘。
- 顶部条：`←返回`(左上) + 输入框（placeholder：**「搜故事、记忆、或某个人」**）+ 右侧「取消」文字按钮。
- **退出职责**：`←返回` 与 `取消` **行为完全一致** = 退出回广场，**不丢广场滚动位置**（不做差异化，消除歧义）。
- **输入框内清空(×)**：有输入时输入框右侧显 `×`，点击 → 清空输入并立即回未输入态（承接 A.5）。

### A.2 未输入态（默认屏）
- **① 热门/推荐**（标题：**「大家在记得的」**）：一排可点**题材 chip**（教室 · 旧物 · 末班车 · 宠物 · 面馆 · 球赛 …，**运营可配**）。**点 chip = 直接进该题材聚合（复用广场 category 过滤），而非拿字面词去搜**——题材词与窗口 category 标签常不同字（如「教室」↔ 校园），字面搜会空；进聚合保证一定有真内容。**无人数、无排名、不悲伤竞赛。运营配置的热门词本身也须过《温柔词表》。**
  > 缺陷复盘定案(2026-08-04)：原「点 chip 以词直搜」会因题材词匹配不到内容而空屏，改为「进题材聚合」。
- **② 搜索历史**（标题：**「你搜过的」**）：最近 ≤10 条，**chip 平铺**（与热门统一视觉，**定死 chip、不做列表**）；每条**可点重搜**、右侧「×」**单条删除**；底部**「清空历史」**。达上限 10 条后**挤出最旧一条**。**仅本地存储(localStorage)**，换设备不同步、可随时清。
  - **清空历史二次确认**：点「清空历史」弹轻确认「确定清空搜索历史吗？」+「清空 / 再想想」，防误删。
- **空态规则**：历史为空 → 只显热门、不显历史标题（不留空块）；**双空（热门未配 + 无历史）** → 给兜底默认屏温柔文案 + 单一引导「输入几个字，找找那段回忆」，不留冷白（对齐 D20）。

### A.3 输入态（有词，实时）
- **输入即联想**（debounce ~200ms），下方出**分区结果**。**本版不做词级联想下拉，直出分区结果**。
- **匹配规则**：**子串包含、大小写不敏感**；**本版不做拼音首字母**。
- **高亮**：命中关键词高亮，作用字段 = **标题 / 昵称 / 近况**（命中即高亮）。
  - **分类参与匹配，但不高亮**（PM 裁定 2026-08-24，解 QA M-2）：分类不渲染在结果卡上，结果卡保持安静克制、不加题材标签，因此无处高亮。原文把分类列入高亮字段与"结果卡字段白名单不含分类"自相矛盾，此处以本条为准。
- 三个分区（各**最多 3 条**；其中**「记忆 / 窗口」「用户」两区带「查看全部 →」，「主题」区不设**——理由见本节末「查看全部去向」下的 PM 裁定）：
  - **「记忆 / 窗口」**：匹配 标题/近况/分类 的窗口卡 → 点进详情。**结果卡字段白名单**：缩略图 + 标题 + 作者 + 暖光质性描述；**不出现记得数/献花数/看过数（红线落到字段级）**。
  - **「用户」**：匹配昵称的用户行（头像 + 昵称 + 一句签名）→ 点进其主页。
  - **「主题」**：匹配的题材 chip → 点进该主题聚合（复用广场按 category 过滤）。**排除「与查询完全相同」的自反命中**（否则打字无真内容时，主题会自反回显一条与查询同名的 chip，使三区不为空、吞掉「没有找到」空态）；仅保留**部分包含**的题材建议（如查「末班」→ 建议「末班车」）。【缺陷复盘定案 2026-08-04】
- **加载态**：联想请求在途，分区区显**轻量占位**（骨架/「正在找…」，不用转圈轰炸，守安静基调）；mock 可瞬时、真接口按此渲染。
- **失败态**：请求失败 → **温柔兜底 + 可重试**，文案「网络有点慢，<u>点一下再试试</u>」，不弹硬错误弹窗。
- **竞态**：**丢弃过期响应**，只渲染最新 q 的结果。
- **查看全部去向**：点「查看全部」→ 该分区类型 + 当前 q 的**全量结果页**（记忆→窗口列表 `?q=&type=windows`；用户→用户列表 `?q=&type=users`）。mock 下同样返回全量本地过滤结果。
  - **「主题」分区不设「查看全部」**（PM 裁定 2026-08-24，解 QA M-1）：主题项点进去就是该题材的全量聚合，与「查看全部」等价，去向不唯一反而困惑。原文"三区都有查看全部"与"主题去向=复用广场 category 过滤"自相矛盾。**2026-08-25：上方分区正文已按本裁定就地回改**（不再靠本注记覆盖原文），本条保留作依据说明。
- **空区**：某分区 0 命中 → **隐藏该空区标题**，只留有结果的区；**三区全空**才进 A.4 空结果态。
- **提交**（回车 / 点任一结果）：把该词**写入历史**（去重、置顶、上限 10、挤出最旧）。

### A.4 空结果态（三区全空）
- 温柔文案：**「没有找到『xxx』，换个词看看？」** + 保留下方热门推荐（给出路），不留冷白。

### A.5 边界与健壮
- 清空输入（或点输入框 ×）→ 立即回未输入态；纯空格/空串不触发搜索。
- **最大输入长度 50 字**：超出在输入端截断/不再接收，超长不触发异常。
- **mock 模式与真后端都要能跑**：mock 从现有 12 窗口 + 8 用户 + 题材本地过滤；真后端预留 `GET /search?q=`，本轮先做 mock、真接口标 TODO。**返回形状钉死（三分区各自 `{items,nextCursor}` 信封，对齐 QA2 铁律）**：
  ```
  GET /search?q=  →  {
    windows: { items:[...], nextCursor },
    users:   { items:[...], nextCursor },
    topics:  { items:[...], nextCursor }
  }
  ```

### A.6 埋点（可拆维度，供 CM-G5 数仓/被接住率看板）
- `search_open{from}`、`search_query{q_len, has_result}`、`search_result_click{section∈记忆/用户/主题, item_id, position}`、`search_history_clear{count}`
- `search_hot_click{term}`、`search_view_all{section}`、`search_history_click{term}`、`search_history_delete_single`
- **不记录任何可拼成公开榜/人数的聚合口径**（守 D19 停留信号仅私域）。

### A.7 红线（必守）
- 热门与结果**无人数、无排名、不做悲伤竞赛**；搜索历史**仅本地私域、可清**；文案（含运营热门词）过《温柔词表》；借完整度不借皮肤。
