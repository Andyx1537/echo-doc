# 视觉选型对比图（2026-08-26）

两组对比，供产品在两个 UI 方案上做选择。**图是主角，本文只解释图上那些数值是怎么来的。**

截图一律 **390×844 的真实手机一屏**（`PhoneFrame`），不拉长画框、不缩放 —— 两组问的都是
「**这一屏**有多空 / 层次有多粗」，撑开画框会让两边都失真。

## 一、广场暖光：连续 vs 三档

| 文件 | 内容 |
|---|---|
| `warmth-side-by-side-screen1.png` | 🔴 **先看这张。** 左连续 / 右三档，同一批卡、同滚动位置（顶部） |
| `warmth-side-by-side-screen2.png` | 同上，两边一起下滚 820px 之后的那一屏 |
| `warmth-continuous.png` | 只有连续版（现状），顶部那一屏 |
| `warmth-tiered.png` | 只有三档版（候选），顶部那一屏 |

### 两版之间唯一不同的那个数

- **连续（现状）**：`warmthLevel = min(1, faces/20)`（服务端 `EchoApi.java warmthLevel(int)`），
  前端 `opacity = 0.25 + warmthLevel * 0.6`（光晕，`PlazaScreen.tsx:131`）与
  `0.4 + warmthLevel * 0.6`（作者行小圆点，`:143`）。
- **三档（候选）**：服务端只下发 `low` / `mid` / `high`，前端映射成固定浓度，**后面两条算式一个字不改**。

### 🔴 分界点（本次自取，不是任何裁定）

| 档 | `faces` | 映射到的浓度 | 光晕 opacity |
|---|---|---|---|
| low | `< 7` | 0.20 | 0.37 |
| mid | `7 – 14` | 0.55 | 0.58 |
| high | `≥ 15` | 0.90 | 0.79 |

浓度取的是各档在连续刻度上的**中位**，让三档版是连续版的「变粗」，而不是整体变亮或变暗。
换一组分界点，这张对比图的结论就会变 —— 已记进卡点信箱。

### 图上这 16 张卡分别是多少人记得

`faces` 铺满 1–40，避免两版长得一样。瀑布是 CSS `column-count: 2`，内容先填满左列再填右列，
所以第一屏看到的是「左列前 4 张 + 右列前 4 张」：

| 卡（`recent` 开头） | `faces` | 连续 opacity | 三档 | 三档 opacity | 那句话变了吗 |

| 它走后，最先空下来的… | 1 | 0.28 | low | 0.37 | — |
| 玻璃上那一点印子… | 2 | 0.31 | low | 0.37 | — |
| 收起来又拿出来… | 3 | 0.34 | low | 0.37 | — |
| 老板记得我不放香菜… | 5 | 0.40 | low | 0.37 | — |
| 午后的阳光和小憩… | 7 | 0.46 | mid | 0.58 | 🔴 静静被记得着 → 一直被记得 |
| 毕业时锁进去的那张纸条… | 8 | 0.49 | mid | 0.58 | 🔴 同上 |
| 收拾搬家时才发现… | 10 | 0.55 | mid | 0.58 | 🔴 同上 |

### 看图能看出来的两件事

1. **光晕本身的差别比想象中小。** 光晕是压在封面底部的一层暖色，实拍封面 + AI 角标的压暗带
   本来就把它盖掉大半；0.28 与 0.37 这种差在一张真封面上基本看不出来。
2. 🔴 **真正响的是那句质性描述。** `warmthPhrase()` 的阈值（0.55 / 0.8）也吃同一个
   `warmthLevel`，所以档位一变，**16 张里有 4 张的说法跟着换了**（上表红字）。
   这 4 处在图上一眼可见，比光晕明显得多。
3. 顺带：三档把两端也压回来了 —— 最暗的从 0.28 抬到 0.37，最亮的从 0.85 压到 0.79，
   **动态范围从 0.57 收到 0.42**。所以「变粗」不止是 16 级变 3 级。

陌生人这一屏是在亲友视角的基础上，再按 §10.3 收掉标着「陌生人不出」的块：

| 块 | 处置 | 依据 |

| B1 顶栏 / B2 封面 / B3 名字 / B4 签名 | 🟢 出 | §10.3「公开」 |
| **B5 羁绊温度**（数字 + 六颗心 + 进度条） | 🔴 裁掉 | §10.3 B5，`N3` 明确 |
| **B7 可见性行**（「🔒 当前：…」） | 🔴 裁掉 | §10.3 B7「仅本人」（§10.6 #2 登记今天亲友也能看到） |

| **B18 这只它的公开卡列表** | ⚠️ **两张图上都没有，不是被裁掉的** | §10.3 自己标着「🔴 缺，整块没有」；代码里确实不存在 |

「暖光面孔墙 / 生命之书 / 温柔的回声 / 献花」长在 `DetailScreen`（另一层，`§10.4` 归属待定），
**这一页本来就没有这几块**，不存在裁不裁的问题。

### B 案那一屏实际剩下什么

**顶栏 + 封面 + 名字 + 签名。就这些。**（见 `stranger-postcard-B-no-emptystate.png`）

调研 §4.4 里那句「只剩封面和名字」不是修辞，是照着 §10.3 一格一格裁完的结果。
⚠️ 但要连着看：这一屏之所以这么薄，**一半是明信片墙被收掉，另一半是 `B18` 公开卡列表还没做**。
两件事应该一起判。

### A 案那一屏

顶栏 + 封面 + 名字 + 签名 + 一面明信片墙（3 张已解锁位，一屏内看得到 2 张半）。
未解锁的虚线空位一个都没有 —— 那正是 A 案与今天 `DetailScreen` 行为的差别。

## 三、造数据与裁剪时做过的假设（可能让对比失真的都列在这里）

1. 🔴 **三档分界点与三个固定浓度是本次自取的**（见上表），没有任何裁定背书。
2. 🔴 **B 案的温柔空态（形态 + 文案）是本次自拟的**，规格只写了「需要一个温柔空态」。
   所以另出了一张不含空态的图，判断请以那张为准。
3. **明信片图用的是运营 seed 封面**（真实比例的图片位 + 一句 caption + 日期），不是空白占位符。
   若真实用户明信片多为竖构图或低质量图，A 案的观感会比图上差。
4. **陌生人视角在代码里不存在**，图上那一屏是用「亲友视角 + 一层只做隐藏的临时 CSS」拼出来的；
   真实实现要在服务端不下发字段（`§10.5` 第 1 条），呈现结果应当与图一致。
5. **暖光那 16 张卡的封面/文案是新造的**，只有 `faces` 是为对比刻意铺开的；
   真实广场的 `faces` 分布若集中在某一段，三档的代价会比图上更小或更大。
6. 图上「小黑」的名字与签名在实拍封面上几乎读不清 —— 🔴 **这是既有缺陷，不是本次引入的**，
   已登记在卡点信箱。它会让 B 案那一屏比图上还薄（三样里两样读不清）。

## 四、临时对比设施怎么撤

这次为出图加的东西，**全部集中在三处**，撤除不涉及任何生产行为：

| # | 位置 | 撤法 |
|---|---|---|
| 1 | `echo-h5-proto/src/dev/`（`VisualCompare.tsx` · `visualCompareData.ts` · `visualCompare.css`） | 整个目录删掉 |
| 2 | `echo-h5-proto/src/main.tsx` | 删掉 `devVisual` / `VisualCompare` 两行与 `React.Suspense` 分支，`render` 恢复成只渲染 `<App />` |
| 3 | `echo-h5-proto/src/components/PlazaScreen.tsx` | `export function warmthPhrase` 去掉 `export`（只为让对比页复用同一个函数、不抄一遍） |

**生产构建不受影响**：入口那一段带 `import.meta.env.DEV` 前置，生产下恒为 false，
`src/dev/` 走的是 `React.lazy` 动态 import，Rollup 会把整棵树静态摇掉。
不加 `?visual=` 参数时，开发模式下的行为也与今天完全一致。

自己跑一遍（先 `cd echo-h5-proto && npm run dev`）：

```
/?visual=warmth&mode=both            连续 vs 三档，并排
/?visual=warmth&mode=continuous      仅连续
/?visual=warmth&mode=tiered          仅三档
/?visual=stranger&plan=both          A vs B，并排
/?visual=stranger&plan=A             仅 A 案
/?visual=stranger&plan=B             仅 B 案
/?visual=stranger&plan=B&empty=0     B 案，连自拟的空态也不给
```
