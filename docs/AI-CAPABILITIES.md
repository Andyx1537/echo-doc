## 0. 一句话结论

- **不是接「一个大模型」**，而是**多类能力接多类模型**：文本类可共用一个 LLM；识别 / 生成 / 视频 / 语音 / 向量各自需要专用模型。
- **「接大模型参数」= 对接一个推理服务**，两种形态：
  1. **租：调云 API** —— 传 `model` 名 + 输入（图/文/音）+ 参数（temperature、尺寸、风格等），按量付费，最快。
  2. **自建：本地部署开源权重** —— 自己跑推理，可控、长期降本、可训练成护城河。
- **落地策略：先租后训**。MVP 用 API 跑通闭环；跑出数据后，把「高频 + 窄 + 要护城河」的能力（基调口吻、内容安全、宠物识别、定妆风格）逐步换成自训小模型。
- **工程上全部走「可插拔 Client 接口 + 配置化」**：切供应商只改配置，不动业务代码。已建接口：`ILlmClient` / `IVectorStore` / `IVisionClient`。

## 2. 统一接入架构（可插拔 + 配置化）

原则：**每类能力一个接口，一个 provider 实现，一份配置**。切换「租/自建/供应商」只改配置与实现类，业务代码零改动。

### 已有接口
- `com.echo.infra.llm.ILlmClient` —— 文本生成（F/G/H/I 共用）。实现：`MockLlmClient`（占位）→ 待加 `ApiLlmClient`（云）/ `LocalLlmClient`（自建）。
- `com.echo.infra.vector.IVectorStore` —— 向量写入/检索（G/H/J）。实现：`PgVectorStore`（pgvector）/ `InMemoryVectorStore`。
- `com.echo.infra.vision.IVisionClient` —— 肖像识别（A）。实现：`StubVisionClient`（桩）→ 待加 `ApiVisionClient`。

### 待建接口
- `IImageGenClient` —— 定妆形象生成（B）。
- `IVideoGenClient` —— 动态生成（C，可后置）。
- `ISttClient` —— 语音转写（E）。
- `IEmbeddingClient` —— 文本嵌入（J；也可并入 IVectorStore 的写入侧）。
- `IModerationClient` —— 内容安全（K）。

### 配置化（env / 配置中心）
每个 provider 用环境变量注入，**API key 走密钥管理、不进代码库**：
```
# LLM
ECHO_LLM_PROVIDER=doubao|deepseek|qwen|claude|local
ECHO_LLM_BASE_URL=...
ECHO_LLM_API_KEY=***
ECHO_LLM_MODEL=doubao-pro-32k
ECHO_LLM_TEMPERATURE=0.8

# 视觉识别
ECHO_VISION_PROVIDER=aliyun|tencent|local_yolo
ECHO_VISION_API_KEY=***

# 图像生成
ECHO_IMGGEN_PROVIDER=wanx|jimeng|openai|local_sd
ECHO_IMGGEN_MODEL=...

# 语音 STT / 向量 / 内容安全 同理
ECHO_STT_PROVIDER=... ; ECHO_EMBED_PROVIDER=... ; ECHO_MOD_PROVIDER=...
```
装配层（`EchoHttpBootstrap`）按 `*_PROVIDER` 选实现注入 `EchoApi`，与现有 llm/vector/vision 注入方式一致。

## 3. 分阶段落地

### P0 — MVP 上线（放自然流量收口测试）
- **必须接真的**：
  - **F 回声生成** → 接 1 路云 LLM（推荐国内豆包/DeepSeek/Qwen，合规 + 便宜 + 低延迟），套用 COPY-GUIDE system prompt。
  - **K 内容安全** → 规则(`CopyGuardFilter`) + 云内容安全 API，AI 生成内容先过审。
- **可继续占位/兜底**：A 识别（桩 + 手动纠正）、B 定妆（能接 img2img 就接，接不上先占位）、E 语音（浏览器）、D 分析（手选词）、C/H/I/J（mock）。

### P1 — 体验补齐
- A 识别接云图像识别（真·按图说话，含多主体+框）。
- B 定妆接 img2img（稳定出「基于照片的卡通形象」）。
- E 语音接云 STT（全端稳定）。
- J embeddings + pgvector 检索（广场共鸣推荐）。

### P2 — 加深 + 自训
- C 动态视频生成。
- H/I 光谱与明日回声。
- 开始把 F/K/A/B 的窄能力**自训小模型**降本、建护城河（对齐 `TECH-AI-PLATFORM.md` 的 build-vs-buy）。

## 4. 「要不要自训」的直接答复

- **短期不必自训**。租 API 就能把 A/B/D/E/F/G/H/J 全部跑通，几天内见效，按量付费。
- **中期值得自训的只有「窄能力」**：口吻/基调、内容安全、宠物识别、定妆风格 —— 这些高频、可积累私有数据、且是差异化护城河。做法是「开源底座 + 我们的数据微调（LoRA/继续预训练）」，不是从零训大模型。
- **不会「一直被迫 call 别人 API 才有更新」**：通用叙事能力可以长期租；我们自训的是**窄而深**的部分，更新靠我们自己的数据回流，不依赖供应商迭代。

## 5. 已拍板决策（2026-07）
1. **P0 LLM**：**先国内跑通（豆包/DeepSeek/Qwen 选一），预留海外（Claude/GPT）做高价值场景**。工程上 provider 可配置，双轨并存。
2. **定妆生成(B)**：**P0 就尽力接 img2img**（通义万相/即梦），尽早出真形象；接不上时回落占位。
3. **接 LLM 的同时，素材自留一份 + 反馈回流做训练语料**（见 §7），为自养模型积累数据。
   > **⚠️ v0.2 限定（2026-08-24）**：「素材自留一份」指**加密留存原件供用户本人取用与导出**，**不等于原图进训练**。训练语料只收**派生物**（`SPEC G0-3` / `DECISIONS CM-D4`），且须经 `IConsentGate` 门控。细则见回改后的 §7。
4. **自养模型**：是，走「开源底座 + 我们的数据微调」路线自己养（选型见 §6）。

## 6. 自养模型选型（可自部署 + 可微调的开源底座）

> 思路：**不从零训大模型**，而是「拿成熟开源权重自部署推理 → 用我们回流的数据做 LoRA/微调」，逐步养成窄而深的护城河。

| 能力 | 推荐开源底座 | 许可 | 养法（用我们的数据） | 起步算力 |
|------|------------|------|--------------------|---------|
| F/G 回声·基调 | **Qwen2.5-7B-Instruct**（中文强）；小=3B，大=14B；或 DeepSeek 蒸馏系列 | Apache-2.0 可商用 | 收集「用户认可的口吻/反馈」→ LoRA 微调口吻+安全 | 单卡 24GB（4bit 可跑 7B）|
| A 宠物识别 | **YOLOv8/v11**（检测+多主体）或 ResNet/EfficientNet（分类）| 需注意 Ultralytics 许可（可换 AGPL 友好替代）| 用户上传图 + 种类标注/纠正 → 微调 | 消费级 GPU |
| B 定妆生成 | **SDXL** 或 **Flux.1-dev** + IP-Adapter/img2img 保相似 | 注意各自许可 | 训练「宠物卡通风格 LoRA」 | 12–16GB |
| E 语音转写 | **Whisper large-v3 / faster-whisper** | MIT | 一般直接用，必要时领域微调 | 中低 |
| J 向量嵌入 | **bge-m3 / bge-large-zh** | 可商用 | 领域语料微调（可选）| 低（CPU 也可）|
| K 内容安全 | bert-base-chinese 微调分类 | 可商用 | 用我们标注的敏感/危机样本训练 | 低 |

- **算力起步**：不必自购卡，先租 GPU（autodl / 阿里 PAI / 腾讯 TI）跑推理与 LoRA；跑出量再考虑自建。
- **落地形态**：自部署模型也包成同一套 `*Client` 接口的一个 provider（如 `LocalLlmClient` 指向 vLLM/Ollama 服务），与云 API **随时切换**。

## 7. 素材保留 & 训练数据回流（含 PIPL 合规）

> **⚠️ 本节口径以 `SPEC-trust-and-compliance.md §CM-G0`（制作人裁定 G0-1~G0-10）为准。**本节是落地清单，凡与该规格冲突处一律以规格为准，不得照抄本节旧文实现。
>
> **v0.2 回改说明（2026-08-24）**：本节 v0.1 整节停留在「宽限期 + 硬删 + 原图进训练」的旧世界，QA 首轮复签点名四处（复签报告 不一致-2 / A-2）：①`t_train_sample` 直接引用原始素材 ref、②未同意素材「用完按策略清理」、③「删除素材 + 训练集同步剔除」、④误用「匿名化」这一法律术语。四处**均已按下文回改**，逐处标注了取代关系。

**目标**：接云 API 的同时，把「**派生特征** + 生成结果 + 用户反馈」自留一份，沉淀成**自养模型的训练语料**。原始素材**只做最小留存供本人取用，不作为训练语料的组成部分**。

### 存什么

| 类别 | 存哪 | 进不进训练语料库 |
|---|---|---|
| **原始素材**（肖像、补充照片、音视频） | 私有对象存储（OSS/COS 私有桶），**按用户维度独立密钥加密落盘**（`SPEC G0-2`，本期真做；缩略图/水印图等派生图同样加密） | **不进。** 仅供本人及授权共同守护者经签名 URL 取用（CM-G4） |
| **派生物**（提交即拆解出的主体 / 背景 / 特征） | 拆解产物表 | 进（须过训练授权门控） |
| **结构化训练样本** | `t_train_sample` | 本体 |
| **反馈信号** | `t_train_sample` 内 | 进 |

- **原始素材**：保留原件 + resourceId，用途是**用户自己看得到、导得走**（CM-G1），**不是训练输入**。
  > **⚠️ 回改留痕**：取代 v0.1 原文「保留原件 + resourceId」被列为训练语料组成的写法。与 `SPEC G0-3` / `DECISIONS CM-D4`「提交即拆解，训练链路只消费派生物，**原图不进训练链路**」冲突——而本节是研发最可能直接照抄的一节。
- **结构化训练样本**（PG 训练语料表 `t_train_sample`）：
  `{ derivedRef(派生物引用，**不收 resourceId / 不收原图字节**), materialRef, consentRef, 识别结果+用户纠正的种类, 定妆候选+用户所选那张+重做次数, 性情词, 回声生成文本+用户反馈(记得/献花/停留时长), 时间 }`
  - `derivedRef` —— **只引派生物**。`ITrainingCorpus` 的写入方法**在类型上就不接受原图**（入参不收 `resourceId` / 字节流），让"原图进训练"成为**编译不过**的事，而不是靠 review 发现。
  - `materialRef` / `consentRef` —— **`SPEC G0-10 ①` 要求的两列强制外键**，分别指回源素材与所依据的授权记录。**没有这两列的派生物表一律不合格，CR 直接打回。**
  > **⚠️ 回改留痕**：取代 v0.1 原文 `{ 输入素材ref, … , consent 标记 }`。旧写法既让训练样本直接挂到原始素材，又把授权做成一个游离的"标记"（无法 join 回溯），两处都不合格。
- **反馈即投喂**：用户「选了哪张定妆 / 把种类纠正成什么 / 对回声的正负反馈」= 高质量偏好数据（用于 DPO/LoRA）。

### 合规红线（PIPL，硬性）

- **训练用途必须独立 opt-in**：与建档时的「允许使用该场景（allowUse）」**分开**，单独一个「同意用于改进与模型训练」勾选，默认不勾，**且不得因勾选使用类而被带动**。
- **未同意**：素材只用于「本次生成」，**不进训练集**；本次生成用完后的中间产物按 `SPEC G0-1` 处置——**置软删标识位，不做物理删除**。
  > **⚠️ 回改留痕**：取代 v0.1 原文「用完**按策略清理**」。「清理」字面即物理删除语义，与 `SPEC G0-1` / `DECISIONS CM-D1`「一律软删、禁止物理与级联删除」冲突。
- **可撤回**：用户随时撤回同意。撤回的处置**分两件事，不要混为一谈**（`SPEC G0-4` / PIPL 第 15 条）：
  1. **停止继续使用** —— 自撤回起不再采用该素材及其**全部派生物**做训练、检索、参考；**训练语料库中的对应样本要剔除**。
  2. **不清除既有产物、不回滚权重** —— **撤回前**已生成的回声 / 定妆形象等属于用户的回忆，**保留**；已训练进模型权重的部分**不需要回滚**（法条明确撤回前处理有效）。
  > **⚠️ 回改留痕**：取代 v0.1 原文「用户随时撤回同意、删除素材；训练集同步剔除」。旧写法把**语料库剔除**（该做）与**权重回滚**（`DECISIONS CM-D6` 明确不做）混在一句里，极易被读成要回滚；且「删除素材」在新口径下是软删而非物理删除。
- **移除素材**：走 `SPEC G0-1` 软删路径 —— 置标识位、立刻对外不可见并停止使用（`DECISIONS CM-D11`：**owner 本人也不可见**）、数据留底、**不做级联清理**。找回走人工客服，无自助入口。
- **去标识化（不是"匿名化"）**：训练样本剥离账号身份，仅留内容与反馈信号。
  > **⚠️ 回改留痕 · 术语，最要紧的一处**：取代 v0.1 原文「**去标识/匿名化**」。按 `SPEC G0-3` 护栏 / `DECISIONS CM-D5`：**拆解 ≠ 免授权**——派生物只要仍可关联到账号，在 PIPL 下即属**去标识化**，**仍是个人信息**，仍受全部授权义务约束。而「**匿名化**」在 PIPL 下是**排除适用**的强主张，主张错了是实质法律风险。**本文档此后不得再出现"匿名化"一词**（描述我们对训练样本做的处理时）。**未拿到训练授权的素材，其派生物同样不得进入训练语料库。**
- 与《隐私政策》《COPY-GUIDE》一致，敏感内容额外过安全审。

### 使用前统一门控（`SPEC G0-10 ②③`，硬约束）

**训练、向量检索、RAG 引用、以及任何把素材或其派生物拿来参考之前**，必须 join 校验**四条件同时成立**：对应 `capability` 的授权 `granted=true`、`revokedAt IS NULL`、源素材 `deletedAt IS NULL`、授权记录本身有效（存在且 capability 与本次用途匹配）。

**任一不成立 → 该素材及其全部派生物退出本次操作**，不是"跳过这一条继续"。

五个校验点（识别 / 定妆生成 / 近况生成 / 向量检索 / 训练）**必须走同一个入口** `IConsentGate.assertUsable(materialRef, capability)`；任何一处自己写 join、自己判 `granted`，**CR 直接打回**。依赖规则（ArchUnit 或等价）：AI 能力模块**不得直接查询 `t_ai_consent`**——把"漏一处"从靠人眼发现变成构建失败。

**核查断言**：训练语料库与向量库中所有样本，回溯到的 consent 必须 100% 满足上述四条件（SQL 见 `SPEC §G0-10 ④`，**期望 0 行**）。随回归跑 + 上线前全量跑 + **上线后按日定时跑**，非 0 行即告警到合规责任人。
