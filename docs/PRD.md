# 回响 (Echo) · 产品需求文档 (PRD)

> 工作代号 **回响 / Echo**。北极星一句话：
> **「念念不忘，必有回响。」**
> —— 那些被深深记得的，从来不会真正走远；它们以回声的方式，一直陪着你。
> Echo = 一个从「温柔的陪伴慰藉」起步、经「共识性互动」、最终走向「群体记忆共鸣」的情感体验平台。
>
> **我们做的事 = 心理慰藉与情感陪伴**，不是对死亡的缅怀。对象是**一切被牵挂、已阔别、久离的人或物**——逝者是其中一类，不是全部。详见 §0.4 基调与对象范围。
>
> **文案红线**：全项目**慎用"逝去/离世/不在了/死亡"等硬词**，一律用隐晦、诗意、有希望的表达（如"远行""换个地方""光里""回声"）；🔴 且**不得在通用位置替用户断言对象已离世**（"故去/天上的 ta"一律禁用）。完整词表与替换对照见 `COPY-GUIDE.md` §1.0/§2.5/§2.6。
>
> ⚠️ **阅读须知（当前形态）**：本产品**当前落地形态 = 「回声·往宠」情感陪伴**（完整规格见《PRD-echo-pet.md》，定案总览见《DECISIONS.md》）。**本文 §1 起的"意识空间 / 共鸣社区 / 对赌养成 / 元宇宙"内容为远期蓝图（第二/三步及其他市场品类的探索出口），不代表当前形态，保留不删**。元宇宙/共鸣设计源于"人基于旧有信息建立起来的通识"，与"过去→未来桥梁"主题一脉相承、不冲突。

## 0.4 🔴 基调与对象范围（v0.6 制作人裁定 · 产品定义级）

> 制作人原话：「我们不会引导人走向那个方向，而且把我们基调上面的**故去之人或者物，扩展成阔别、久离、牵挂之人或者物**就好了。做的事是**心理慰藉**，别把自己滑向单纯的对死去这个事物的缅怀。」

### ① 对象范围：一切被牵挂的人或物

产品的对象**不限于已经离世的人或宠物**，而是**一切被牵挂、已阔别、或久离的人或物**：

| 类别 | 举例 |
|---|---|
| 已离世 | 逝去的宠物、逝去的亲人（**完整保留，仍是最重要的一类**） |
| 阔别 | 异地的家人、移民的挚友、久病分居的伴侣、搬离的旧居 |
| 久离 | 失联的老友、断亲的家人、走散的猫 |
| 单纯牵挂 | 长期不在身边但仍挂在心上的任何人或物 |

🔴 **这是扩展，不是替换。** 逝者与离世宠物的场景**完整保留**，哀伤语境下的克制与温柔**一个字都不放松**——`COPY-GUIDE.md` §2.1 禁用词、§3 D 类双重把关、§5 情绪安全审查清单**全部原样有效**。放宽的是覆盖人群，不是把关强度。

### ② 自我定位：心理慰藉，不是对死亡的缅怀

产品做的事是**情感陪伴与心理慰藉**。自我定位、对外表述、功能说明**一律落在这里**，整体叙事**不进入**纪念 / 追思 / 悼念这一类死亡语境。

### ③ 不引导用户走向死亡相关的方向

措辞与引导语**不得把用户往"这个人 / 这只宠物已经不在了"的方向推**。**用户自己处在什么状态，由用户自己带来**；产品只提供一个能承接的空位。执行细则（含替换对照表）见 `COPY-GUIDE.md` §1.0 ③、§2.5、§2.6。

### ④ 🔴 对象在世时的边界：只放宽措辞，不模拟「ta 发来消息」

**结论**：对象**在世**时，**只放宽基调与措辞**；内容仍围绕**用户自己的记忆与寄托**，**不模拟在世者"发来消息"**，不做其肖像的拟真生成、不做声音克隆。

**理由（必须连同结论一起读，不要只记结论）**：

> 逝者场景的授权来自**近亲属**——依《民法典》第 994 条，死者的肖像、名誉、隐私等受法律保护，维权主体为近亲属，因此"取得近亲属同意"是一条**可走通的授权路径**。
> **在世者的肖像与声音属于本人的人格权**（《民法典》第 1018、1019、1023 条），授权主体**只能是本人**。用户 A 上传用户 B 的照片，**A 无权代 B 授权**；平台据此生成 B 的拟真形象、或以 B 的口吻发来消息，**是直接的法律敞口**——性质上不是"风险偏高"，而是**没有合法授权基础**。

🔴 **这条边界不是保守，是没有合法授权可依。** 未来若要放开，**前置条件是"取得对象本人可验证同意"的机制落地**，而不是"我们觉得可以放开了"。在该机制落地前，任何以"基调已经放宽了"为由要求放开在世者拟真的提案，**引用本条关闭，不需要重新拍板**。

**连带**：与 `COPY-GUIDE.md` §2.4（CR2/CM2 诚实标识）同向不冲突——那条管**逝者场景下不许拟真到"它还活着"**，本条管**在世场景下根本不生成 ta 的口吻**。两条并存。

### ⑤ 为什么这么改（写下来，防止后人当成保守而收回去）

1. **降低进入门槛**：很多人不愿承认自己在"悼念"，但都愿意承认自己"想念"。**"故去"这个词本身在门口筛人，筛掉的往往是最需要的那批。**
2. **品类待遇不同**：殡葬与逝者相关品类在境内**广告投放与内容审核上有额外限制**；定位为情感陪伴与心理慰藉，**买量与内容分发的空间完全不同**（与 `DECISIONS.md F2`「靠定位一致性而非话术去规避品类风险」同一思路——定位一致性本身就是可运营性）。
   ⚠️ 现行对外品类词「数字纪念空间」（`DECISIONS.md GTM1`）与本条冲突，已登记待另行裁定。

## 0.5 产品战略：三步走（v0.5 定调）

> 核心判断：先用**单人自洽、低门槛、强情绪价值**的体验广泛获客，再叠加人与人的交互，最后升华为群体记忆的精神共同体。三步共享同一套底层（向量档案 / 回声 / 空间 / 共鸣），逐层解锁。

| 步骤 | 名称 | 目标 | 核心内容 | 状态 |
|---|---|---|---|---|
| **第一步** | **情感地基** | 广泛获客、验证情感 AI 陪伴机制 | **回声·往宠**：从用户素材温柔"唤回"那只让你念念不忘的宠物，定时捎来它的近况，安静陪伴、慢节奏安抚。子阶段升华：对象扩展到"某位重要的人"（措辞慎重，见 `PRD-echo-pet.md` §0 语言规范；🔴 对象在世时受 §0.4 ④ 边界约束） | **进行中**（本轮规格化） |
| **第二步** | **交互层** | 有用户体量后建立人与人交互 | 共识性互动玩法（**对赌/约战即此层一种题材**）、社区雏形、共鸣者互访 | 蓝图（本 PRD §1–§9 大部分内容归此） |
| **第三步** | **精神共同体** | 升华主题，达成"Echo" | 向量映射：每人在主观印象中不断丰富所在意的个体 → 群体记忆映射绘制 → 基于集体回忆产生共鸣 | 愿景 |

**关键洞察**：现已建成的技术地基（`MindProfile`/`SelfVector`、`IVectorStore`(pgvector)、`ILlmClient`、`Echo` 实体、`MindSpace`+四轴场景、`scheduler`、Unity 写实空间+卡通形象）几乎为第一步"量身定做"，复用率高，本次转向不浪费既有投入。

### 0.5.1 品类外延主线（v0.6 改写）

**原表述**：宠物 → 逝去的人 → 我的光谱。
🔴 **现表述**：**宠物 → 被牵挂的对象（人 / 物 / 地方）→ 我的光谱**。

主线的第二段**不再是"逝去的人"，而是更宽的"被牵挂的对象"**；**逝者是其中一类，不是全部**。

| 品类 | 状态 | 门槛与依据 |
|---|---|---|
| **宠物** | ✅ **P0 唯一落地品类** | 最安全的试验田——无肖像权与法律包袱（`PRD-echo-pet.md` §1） |
| **被牵挂的人（在世）** | 🔜 后置 | 受 **§0.4 ④** 约束：只放宽措辞，**不做拟真模拟**。放开的前置条件是"对象本人可验证同意"机制 |
| **被牵挂的人（已离世）** | 🔜 后置，需专门框架 | 需专门伦理 + 法务框架（近亲属授权、身份核验、内容护栏）后再评估 |
| **被牵挂的物 / 地方** | 🔜 能力预留 | 旧居、老物件、走散的猫——**法律包袱最轻的一段外延**，可先于"人"探索 |
| **我的光谱** | 🟡 概念已定 | solo 自我回溯，非公开评价他人；心理安全底座优先 |

**为什么把"物 / 地方"单列**：它在扩展后的对象范围里**法律门槛最低**（无人格权问题），却同样承接"牵挂"这一情感，是"宠物之后、人之前"最自然的一跳。原主线直接从宠物跳到"逝去的人"，跳过了这一段。

> 下文 §1 起为第二/三步蓝图（意识空间/共鸣/对赌），第一步「回声·往宠」的完整产品规格见独立文档 **《PRD-echo-pet.md》**。

## 1. 产品概述

### 1.1 核心创意
传统社交/元宇宙是「所有人共享同一个世界」。本产品反其道：**每个人活在由自己意识投射出的个人世界里，只有与你"共鸣"的人才会被渲染进来**。在这个被克制呈现的世界里，人与人通过形象、宠物互相吸引，并以「摆摊约战 + 压注对赌」作为最核心、最有张力的强交互。

三大支柱：
1. **意识空间**：用户自拟少量偏好 → LLM 推断补全 → 形成个人向量 → 程序化拼装出印象式 3D 个人世界。
2. **共鸣社区**：基于向量相似度匹配"共鸣者"，以异步回声 / 实时在场叠加渲染进你的世界。
3. **对赌养成**：携带参战宠物，摆摊约战、压注，赢家通吃奖池；宠物经 AR 捕获、吞噬合成增值，且每只宠物拥有唯一ID（"区块"抽象）。

### 1.2 目标用户

> ⚠️ **本节属远期蓝图口径**（见顶部横幅）。**当前形态的目标人群见 §0.4 ① 对象范围**与 `PRD-echo-pet.md` §1.1——两者是不同品类的不同人群，不要混用。

- 喜欢"独处感 + 偶遇式社交"的玩家（反高压社交）。
- 收集养成 / 抽卡 / NFT 资产爱好者。
- 轻竞技、对赌博弈爱好者。

### 1.3 差异化
| 维度 | 传统元宇宙 | 回响 |
|---|---|---|
| 世界 | 全局共享同步 | 个人意识投射，异步独立实例 |
| 社交 | 始终在线人群 | 仅共鸣者被渲染（克制、稀缺、有意义） |
| 网络 | MMO 级实时同步（重） | 异步优先（轻），实时按需叠加 |
| 资产 | 中心化 | 唯一ID/区块抽象，可平滑升级真链 |

### 1.4 美术风格基调（已定调，O9 关闭）
**整体定位：「写实空间 + 卡通角色/宠物」的混合风格。**

| 对象 | 风格 | 意图 |
|---|---|---|
| **空间 / 环境** | **写实**（拟真材质、光影、场景） | 营造沉浸感与**"可回忆、熟悉"**的氛围——写实场景更能勾起记忆，直接服务于"意识/记忆投射空间"的产品内核 |
| **自身形象 (Avatar)** | **偏卡通**（亲和、风格化） | 降低恐怖谷、提升亲和与代入；便于轻量换装与个性表达 |
| **宠物** | **卡通**，但**整体定制不宜过于夸张**（克制的卡通，造型适度） | 保持可爱亲和与辨识度，又不流于浮夸怪诞，便于规模化生成与突变变体 |

**设计要点**：
- 写实环境 + 卡通角色的**对比**让角色/宠物在视野中聚焦、突出，情感更暖。
- 与"定势组合（年代感/主题预制）"结合：写实场景以**年代感定势**表达"记忆里的熟悉场所"。
- **先试落地、再迭代**：先用此基调做出可玩样例，依据实际观感与性能再调整。
- 落地依赖客户端（Unity）与美术资产产线；P1 后端不受此影响。

## 2. 已确认的关键设计决策（讨论沉淀）

> 这些是与制作人/需求方逐条拍板的结论，作为后续所有设计的约束。

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 货币/资金 | **货币无关 + 可插拔结算**。国内虚拟币（不可提现）起步；出海加密代币是同一结算接口的另一实现。玩法代码不感知币种。 |
| D2 | 合规口径 | 基座期按"娱乐玩法 + 虚拟币"合法运营；出海/可提现是后期独立业务分支（需牌照/KYC/AML/地理屏蔽），技术上预留不堵死。 |
| D3 | 上链 | 先**中心化 DB +「唯一ID/区块」抽象**，不接真链；为公链/联盟链预留迁移接口。 |
| D4 | 空间形态 | **写实空间 + 卡通角色/宠物**的混合风格（v0.3 调整，原"印象式非写实"作废）；第一/第三人称；资产模块化拼装。详见 §1.4。 |
| D5 | 场景驱动 | 用户**自拟少量偏好** → **LLM 推断补全填充** → 个人**向量**为起点；场景以**固定搭配/年代定势组合**为主 + **少量实时元素**（降算力、提实时与可互动）。 |
| D6 | 共鸣呈现 | 异步回声 + 实时在场**两者都要**；**实现先全异步**，后续按反馈加实时。**主控（开房玩家）可配置共鸣细节**（是否广播 / 各自异步探索）。 |
| D7 | 交互深度 | 旁观 + 手势/留痕 → 摆摊 → **可直接约战/压注**（社区直接预埋对赌入口）。 |
| D8 | 客户端 | Unity 一套工程；先 H5(WebGL) 验证 → 再移动 App → 未来 AR Foundation。服务端 = Aengine。 |
| D9 | 分期 | 社区基座 → 宠物 → 对赌 → 出海代币化。 |

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 意识档案 (Consciousness Profile) | 用户的偏好/记忆碎片/标签集合 + 由其生成的个人向量。 |
| 个人向量 (Self Vector) | 表征用户意识倾向的向量，用于场景生成与共鸣匹配。 |
| 意识空间 (Mind Space) | 由个人向量驱动、程序化拼装出的个人 3D 世界实例。 |
| 定势组合 (Preset Set) | 预制的、带年代感/主题感的场景资产搭配，复用以降算力。 |
| 共鸣 (Resonance) | 两个用户向量相似度达到阈值的关系。 |
| 回声 (Echo) | 共鸣者留在你世界里的异步痕迹/录像式幽灵。 |
| 主控/开房玩家 (Host) | 拥有并配置某个意识空间会话的玩家。 |
| 唯一区块 (Unique Block) | 资产（宠物等）的唯一ID载体，中心化实现，预留上链。 |
| 结算 (Settlement) | 对赌奖池的托管、判定与发放。 |

## 5. 功能需求

> 标注：【P1】=基座先做；【P2/P3/P4】=后续分期；【预埋】=本期只留接口/占位。

### 5.1 账号与形象【P1】
- **F-ACC-1** 注册/登录/会话（复用 Aengine 账号与 `PlayerSession`）。
- **F-AVT-1** 轻量换装形象：若干部位（发型/脸/体型）+ 时装位（≥3 个槽位）。
- **F-AVT-2** 资料卡：展示形象、签名、（后期）参战宠物、共鸣统计。
- **F-AVT-3** 形象数据进入资产档案，可被他人在共鸣场景中查看。

### 5.2 意识档案 & 个人向量【P1】
- **F-MIND-1** 用户自拟偏好：引导式输入若干"记忆碎片/偏好标签"（如：年代、色调、意象、音乐、情绪关键词）。
- **F-MIND-2** LLM 推断补全：基于用户少量输入，调用 LLM 扩写/补足偏好，生成结构化偏好集。
- **F-MIND-3** 个人向量生成：将偏好集编码为 Self Vector，落库（向量存储）。
- **F-MIND-4** 向量可演进：用户行为（捕获、约战、停留）反哺向量（P2 起增强）。
- **设计约束**：以**用户自主向量为起点**（用户可见可控），LLM 仅做补全，不黑盒主导。

### 5.3 意识空间生成【P1】
- **F-SPACE-1** 由 Self Vector → 选取匹配的**定势组合（年代感/主题预制资产）**拼装个人 3D 场景。
- **F-SPACE-2** 在定势骨架上叠加**少量实时/动态元素**（天气、光影、点缀），以兼顾"独特感"与"低算力/高实时"。
- **F-SPACE-3** 第一/第三人称视角切换；**写实空间渲染 + 卡通角色/宠物叠加**（美术基调见 §1.4）。
- **F-SPACE-4** 场景可复访、状态持久化（每个用户的世界是独立实例）。
- **性能原则**：定势组合可缓存复用，避免每次实时全量生成；动态元素受预算上限约束。

### 5.4 共鸣匹配【P1】
- **F-RES-1** 向量相似度匹配：为当前用户检索 Top-N 共鸣者（相似度阈值可配）。
- **F-RES-2** 匹配可附加规则：在线状态、地域、活跃度、好友优先等加权（可后置）。
- **F-RES-3** 共鸣结果产出"可被渲染进我世界"的候选集。

### 5.5 共鸣呈现【P1 异步 / 实时后置】
- **F-SHOW-1**【P1】**异步回声优先**：共鸣者以"回声"（痕迹/录像式幽灵/留痕信物）出现在你的世界。
- **F-SHOW-2**【预埋→后置】实时在场：共鸣者实时化身出现（轻在场，弱同步），按反馈增量上线。
- **F-SHOW-3** **主控可配置共鸣细节**：开房玩家可设置"是否广播 / 各自异步探索 / 共鸣强度阈值 / 是否开放约战"。
- **实现策略**：P1 一律以异步语义实现（快照/留痕），实时仅作为后续叠加层，不返工。

### 5.6 社交交互【P1 起，逐步加深】
- **F-INT-1**【P1】旁观 + 手势/表情 + 留痕（给共鸣者留下信物/标记）。
- **F-INT-2**【P1】好友/关注/共鸣记录。
- **F-INT-3**【P1 占位 / P3 启用】**个人摊位**：P1 仅占位与展示；宠物/对赌上线后升级为"约战入口"。
- **F-INT-4**【P3】摆摊约战入口：从摊位直接发起对赌邀请。

### 5.7 对赌 PvP【P3 主体，P1 预埋入口】
- **F-BET-1** 约战房间：双方进入、确认参战宠物（P2 后）、压注。
- **F-BET-2** 玩法可插拔（玩法接口 + 适配器）：
  - 内置：剪刀石头布、猜枚（首批）。
  - 扩展：更多自研玩法、**外接第三方游戏**适配。
  - 模式：双方主动选择 / 随机。
- **F-BET-3** **可验证随机**：承诺-揭示（commit-reveal）或 VRF，保证结果不可被任一方/服务器操纵。
- **F-BET-4** 奖池结算：托管双方注金 → 判定胜负 → **赢家通吃，输家归零** → 平台**抽水（rake）**。
- **F-BET-5** 结算走"货币无关结算接口"（见 5.10）。
- **F-BET-6** 反作弊、防串通、对局回放与申诉。

### 5.8 宠物系统【P2，P1 预埋档案位】
- **F-PET-1** AR 捕获：类宝可梦 AR 拍照；**相似地理/地貌只产出近似结果**；可触发**突变**（影响战斗性能 / 外观）。
  - 捕获判定建议起步用 **GPS 地理围栏 + 地块标签近似**，图像识别为可选增强（成本权衡，见风险）。
- **F-PET-2** 养成：等级/属性成长。
- **F-PET-3** **吞噬合成**：同种宠物合并叠加，做成"万级别大池"增值效果；被吞者销毁、吞噬者属性/价值放大。
- **F-PET-4** **唯一区块**：每只宠物有唯一ID（区块抽象），价值可因吞噬放大（见 5.9 对"唯一性 vs 吞噬"的处理）。
- **F-PET-5** 突变外观：起步用**预制美术组合**驱动（部件/配色组合），AIGC 实时生成为后期可选。
- **F-PET-6** 宠物作为参战单位接入对赌。

### 5.9 资产 / 唯一ID（区块抽象）【P1 抽象，P4 可上真链】
- **F-ASSET-1** 统一资产档案：形象、宠物等均挂在"唯一区块"抽象之下，ID 全局唯一、不可篡改（中心化实现 + 哈希链/审计日志）。
- **F-ASSET-2** **唯一性 vs 吞噬的处理（已确认：方案 B）**：
  - **采用方案 B**：吞噬即**销毁被吞者区块**，价值/属性并入吞噬者。
  - 语义对齐："每只宠物都算一个区块/唯一ID"指**任一时刻存续的宠物**；被吞者执行"销毁(burn)"并留**墓碑审计记录**（仅作溯源/审计，不再是可持有资产）。
  - 吞噬者价值随累计吞噬放大（计入其属性与价值字段）。
  - 优点：实现简单、资产总量自带通缩闸门；代价：被吞个体不可再独立存在（已确认接受）。
- **F-ASSET-3** 预留上链迁移接口（资产铸造/转移/查询抽象），P4 可对接公链/联盟链。

### 5.10 经济 / 钱包 / 结算（货币无关·可插拔）【贯穿】
- **F-ECO-1** 钱包：用户余额、流水、交易记录。
- **F-ECO-2** **结算抽象接口** `ISettlement`：定义 充值/扣减/托管/发放/抽水；
  - 实现一：`VirtualCoinSettlement`（国内虚拟币，不可提现）【P1/P3】。
  - 实现二：`CryptoSettlement`（加密代币，可提现，含 KYC/AML 钩子）【P4】。
- **F-ECO-3** 商城：形象/时装、捕获能量、突变加成道具等（变现，见第 8 节）。
- **F-ECO-4** 风控：交易限额、异常监测、反洗钱钩子（P4 强化）。

## 6. 关键流程

### 6.1 新用户首启（P1）
```
注册/登录 → 引导自拟偏好(若干) → LLM 补全 → 生成个人向量
→ 拼装意识空间(定势组合+动态点缀) → 进入第一/第三人称世界
→ 共鸣匹配 → 异步回声出现 → 可留痕/手势/加好友
```

### 6.2 共鸣呈现（P1 异步）
```
进入世界 → 拉取我的向量 → 检索共鸣者Top-N → 取其回声快照
→ 合并渲染进我的场景（受主控配置：广播/异步/阈值约束）
```

### 6.3 对赌对局（P3）
```
摊位发起约战 → 对方接受 → 选参战宠物 → 双方压注(托管)
→ 选玩法/随机 → 可验证随机产生结果 → 判定胜负
→ 赢家通吃奖池 - 平台抽水 → 入账/流水 → 可回放/申诉
```

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 异步优先 | P1 无全局实时同步；以快照/留痕/事件驱动，降低服务端压力。 |
| 承载 | 个人世界为独立实例；共鸣检索为读多写少，走缓存 + 向量索引。 |
| 性能 | 定势组合缓存复用；动态元素有预算上限；客户端首屏 < 目标值（待定）。 |
| 公平性 | 对赌必须可验证随机（commit-reveal / VRF），服务器不可操纵结果。 |
| 安全 | 资产唯一ID 防篡改（哈希链/审计）；钱包交易幂等、可对账。 |
| 合规 | 基座虚拟币不可提现；可提现/代币化版本需牌照、KYC/AML、地理屏蔽。 |
| 可扩展 | 玩法、结算、资产上链均为接口可插拔，便于分期与出海。 |

## 8. 盈利模型

| 来源 | 说明 | 阶段 |
|---|---|---|
| 对赌抽水 (rake) | 每局奖池抽 3–10%，核心收入 | P3 |
| 形象/时装付费 | 皮肤、展示位，纯利不破坏平衡 | P1 |
| 捕获/突变加成 | 探索能量、提升突变率/稀有度道具 | P2 |
| 资产二级市场 | 宠物交易手续费 + 版税 | P2/P4 |
| 第三方玩法接入 | 外接游戏导流与流水分成 | P3+ |
| 代币化/出海 | 加密结算、可提现生态（需合规） | P4 |

**收益展望与风险**：抽水是赌博类最稳收入，但与合规强绑定；Web3 资产投机属性易暴涨暴跌伤留存；AR+客户端+（可选）链三线投入前期成本高、回本周期长。建议**先用 P1/P3 虚拟币模型验证留存与付费意愿，再决策 P4 出海投入**。

## 9. 数据模型概要（映射 Aengine 持久化）

> 均以 Aengine 的 `@Table/@Column/@Pk/@Index/@Cache` 注解实体 + `IRepository` 落地，仓储用自写 `CachedPgRepository`（复用 Aengine 缓存层）；**单库 PostgreSQL** 主存，向量走同库 pgvector。

- `Account` 账号
- `Avatar` 形象（部位/时装位）
- `MindProfile` 意识档案（偏好集 + 向量引用）
- `SelfVector` 个人向量（向量落同库 pgvector 列 + 关系元数据落 PostgreSQL）
- `MindSpace` 意识空间实例（定势组合引用 + 动态参数 + 主控配置）
- `ResonanceRecord` 共鸣记录
- `Echo` 回声（共鸣者留痕快照）
- `Friendship` 关系链
- `Stall` 摊位
- `AssetBlock` 唯一区块（资产基类，含血统链）【P2】
- `Pet` 宠物（继承 AssetBlock）【P2】
- `Wallet` / `TransactionLog` 钱包与流水
- `BetMatch` / `BetResult` 对局与结算【P3】
