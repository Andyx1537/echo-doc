# 级联交付账本：公开互动、账号切换与审核重提

任务 ID：`PD-20260903-public-interaction-auth-review`

决策范围：`G-31`–`G-33`

状态：`PRODUCT_CONFIRMED / DISTRIBUTED`
基线分支：三仓 `develop`；基线标签 `baseline-2026.09.03`

## 统一增量

| 项目 | 内容 |
|---|---|
| 原有基线 | Work 是唯一公开实体；匿名可读详情但公开写需手机号；驳回/审核存在目标状态但互动、手机生产契约不完整 |
| 当前实现事实 | 前端缺完整 WorkDetail、评论互动和真实手机号流程；后端有 Work/匿名账号骨架，但缺作品评论收藏、手机号挑战解析和作品版本化重提的完整链路 |
| 新定案 | 评论最多两层并保留实际回复对象；三类删评权限；收藏作者不可见；已有手机号切回原账号且不迁移匿名资料；驳回同 workId 新版本重提审核 |
| 不变项 | 公开事实只归 workId；匿名写零落库；私域资料不因陌生人互动回流；下架申诉不能被编辑入口绕过 |
| 失败策略 | 权限、关系、验证码、版本或审核条件不明均 fail closed；手机流程失败保留匿名会话 |

## 拆分工作线

1. `WI-COMMENT`：评论 DTO、二级封顶关系、热门/最新读取、删除治理、真接口与页面状态。
2. `WI-FAVORITE`：私有收藏、本人收藏页、作者/公开信息零泄露。
3. `WI-PHONE`：挑战、验证、归属解析、切换确认、会话替换与返回路径。
4. `WI-RESUBMIT`：作品内容版本、编辑草稿、重提 CAS、审核工单和作者前台。
5. `WI-QA-INTEGRATION`：契约样本、迁移、真后端联调、受影响回归与精确构建签收。

## 三方回执门

- 前端：页面/路由/草稿与账号切换状态、最小接口缺口、分支和预计窗口。
- 后端：schema/API/事务/审计/迁移/安全与预计窗口。
- QA：可测性、数据与环境、用例映射、阻断项和签收条件。
- 三方共同确认同一 API/DTO/错误/状态版本前，状态不得进入 `CONTRACT_READY`。

## 产品仍需决定

本包不等待产品补充即可进行技术评估。若技术评估证明以下事项会改变用户体验，再回产品定调：热门评论权重的首组数值、作品作者删评是否需要二次确认、收藏页的分组方式。三项均不得阻塞对象和接口骨架。
