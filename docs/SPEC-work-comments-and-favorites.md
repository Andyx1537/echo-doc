# 作品评论、二级回复与收藏 · 产品及工程规格

> 状态：已定案；上位裁定 `DECISIONS G-31`。公开互动唯一目标为 `workId`。

## 1. 用户体验

- 作品详情展示一级评论；每条一级评论下平铺二级回复。
- 用户可以回复一级评论，也可以回复任意二级回复；后者显示为“回复 @昵称”，但仍位于同一个二级区，不产生第三级缩进。
- 一级评论支持“热门 / 最新”切换；同一一级评论内的回复按创建时间正序，分页展开。
- 匿名用户只在 Plaza 作品详情页读取同一热门排序的前 3 条一级评论，以及每条由服务端裁剪的受控回复预览；不能展开完整分页、发表、回复或执行治理动作。

## 2. 数据关系

```text
一级评论: rootCommentId=null, replyToCommentId=null
回复一级: rootCommentId=<一级ID>, replyToCommentId=<一级ID>
回复二级: rootCommentId=<一级ID>, replyToCommentId=<被回复的二级ID>
```

后端校验 `rootCommentId`、`replyToCommentId` 与 `workId` 属于同一可见评论树。前端不得自行推算或改写归属。

## 3. 删除和治理

| 动作人 | 范围 | 公开结果 | 审计原因 |
|---|---|---|---|
| 评论者 | 自己的评论/回复 | 软删 | `author_deleted` |
| 作品作者 | 自己作品下评论的隐藏、删除、举报 | 软删/隐藏/进入举报治理 | `work_owner_moderated` 或举报理由码 |
| 平台 | 全局审核、隐藏、删除和规则处置 | 软删/屏蔽 | 平台理由码 |

- 普通用户只能删除自己写的内容；任何角色都不得编辑他人评论，作品作者的治理能力不产生文本改写入口。
- 用户删除自己创建的一级评论时，同一事务软删该一级评论及其全部二级回复；公开读取不返回占位或树内任何节点，任何人不得继续回复该树。作者或平台移除一级评论时遵守相同的展示封闭边界。
- 删除二级回复时只软删该回复，不连带删除同根的其他二级回复。
- 二级回复的被回复目标删除后，其余回复继续展示，目标统一表达为“回复一条已删除评论”，不得暴露已删除正文。
- 级联软删只改变在线可见性，不物理删除评论、历史互动、通知或审核证据。
- 删除不得篡改历史互动、通知或审核流水；计数由服务端在同一事务中校正。
- 评论菜单按身份展示“删除 / 举报”，隐藏按钮不替代服务端鉴权。
- 作品作者菜单允许“隐藏 / 删除 / 举报”，但不出现“编辑”；隐藏是否可恢复、恢复后的排序位置及失败提示仍待技术提出并由产品确认。

## 4. 收藏

- 收藏为 `(accountId, workId)` 幂等私有事实，支持收藏/取消收藏。
- 作者不收到收藏消息，不得查看收藏人或收藏次数；公开 DTO 不返回收藏数。
- 收藏者可在自己的收藏页查看仍可见作品；删除、下架或失权作品按不可见处理。
- 收藏不回流私域生成，不作为作者消息，也不在当前阶段进入线上推荐排序。

## 5. 热评排序最小机制

热门只排序一级评论，目标是可读和有讨论价值，不追逐争吵：

```text
hotScore = 质量合格后的互动贡献 + 合格回复贡献 + 新评论探索增益 - 时间衰减 - 风险/异常惩罚
```

- 点赞、有效回复只能使用去重且通过风控的事实；作者置顶、付费、情绪浓度不加分。
- 新评论获得有限探索位；异常账号、刷量和被平台限制的评论不得进入热门。
- 精确权重由实验配置管理；排序版本随分页游标冻结，避免翻页重复和漂移。
- “最新”按服务端 `createdAt DESC, commentId DESC` 稳定排序。

## 6. 验收

1. 回复二级评论后仍只显示两层，并准确显示被回复者。
2. 跨作品伪造 root/reply 关系失败且不落库。
3. 普通用户只能删除自己内容；作品作者可隐藏、删除、举报但不能编辑他人评论；平台全局治理权限正确。
4. 根评论删除后整棵评论树从公开读取消失；任一节点删除失败则整笔事务回滚。
5. 收藏幂等；作者端没有通知、收藏名单和收藏数。
6. 匿名仅在 Plaza 作品详情读取热门一级 3 条与受控回复预览，不获得完整分页游标，所有写操作零落库。
