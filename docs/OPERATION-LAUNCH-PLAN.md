## 1. 运营判断与本期目标

### 1.1 当前阶段判断

项目已完成策略、产品定案、接口契约、验收用例与 H5 可点击产品形态，当前应定义为 **“可演示原型 → 可用的邀请制 MVP”** 过渡期。

本期最重要的不是增加第二步社交功能，也不是启动 App，而是证明一个小而完整的闭环：

```text
游客浏览一扇窗 → 感到共鸣 → 建档 → 首次回访看近况 → 留下轻互动/分享 → 次日愿意回来
```

### 1.2 P0 成功定义（先验目标）

| 层级 | 指标 | P0 内测门槛 | 用途 |
|---|---:|---:|---|
| 可用性 | TC-01～TC-12 通过率 | 100%，阻断缺陷为 0 | 能否对真实用户开放 |
| 建档 | 游客到建档完成率 | ≥35% | 判断建档负担是否过重 |
| 首次价值 | 建档后首次查看近况率 | ≥70% | 判断首日体验是否建立期待 |
| 回访 | D1 回访率 | ≥25% | 验证“回声”是否有留存价值 |
| 情感互动 | 回访用户中至少一次互动率 | ≥30% | 判断内容是否促成自然表达 |
| 裂变意愿 | 建档用户分享率 | ≥10% | 判断“一扇窗”是否具有传播性 |
| 安全 | 红线文案/严重隐私事件 | 0 | 情感产品的硬门槛 |

> 这些是 P0 的决策阈值，不是对外 KPI。样本量不足 100 名时，只做方向判断，并结合访谈决定，不用小样本“优化”数值。

### 文档治理规则

1. **规格变更先记 `DECISIONS.md`，再同步 PRD / API / 验收。** 不接受只改原型、不改验收口径的需求。
2. **每周一更新本计划的状态与风险，周五更新数据和结论。** 只写“完成物、阻断项、下周决策”，不写泛泛进度。
3. **运营不以页面数量验收。** 每项需求须关联一个用户行为、一个埋点、一个验收用例或一条风险护栏。
4. **第二步功能默认冻结。** 共同守护、深社交、~~付费购买~~、App 和复杂 AI 中台均不进入 P0，除非能直接解除 P0 阻断。
   - ⚠️ **2026-08-25 回改**：🔴 **「付费购买不进 P0」已被推翻。** 现行口径是 **P0 就上订阅**（早验证付费意愿），配 5 条克制护栏：① 订阅入口克制、非打断，不在建档/首个回声/告别等情绪高峰弹付费；② 🔄 **档位差异只体现在「尚未生成」的服务产出上**（2026-08-25 由 `DECISIONS §G⁗ CR-M②′` 三分改写，原文 ~~绝不设「悲伤付费墙」，纪念内容本体永不锁进付费~~ 已划除保留）—— 现口径：**你自己放进来的素材，以及我们已经交付给你的产出，任何时候都能查看、播放、下载、导出，🔴 不因档位差异、降档或停止付费而减少、失效或不可访问**；一句话即 🔴 **已有的一样多，能新增的不一样多**。🔴 **对外文案必须与协议同源，不得自行改写这句话**（《民法典》第 498 条：有两种以上解释的作出不利于提供方的解释）；③ 只卖体验/保存/呈现增值，不卖曝光、不卖共鸣、无作者分成；④ **共鸣厅内零交易**；⑤ 实体纪念品/家庭页等重服务仍延到 P1+。<br>**依据**：`DECISIONS.md §G⁗ CR-M`（2026-07-28 定案，明确**不采纳**「P0 全免费」）+ `§G⁗′ CM3`（2026-08-04 运营再次建议延后，裁定**维持 CR-M 不改**）+ `OPERATION-SUBSCRIPTION-STRATEGY.md §1`。<br>**其余四项（共同守护、深社交、App、复杂 AI 中台）冻结不变。** 另注：`H10` 建议立为铁律——**订阅开卖必须与收入看板 + 变现护栏面板同批上线**，不接受「先收钱后补账」（待拍板）；实现侧尚未立项，见 `H13`。

## 5. P0 运营方案

### 5.1 种子用户招募与分层

首批不追求泛流量，优先招募愿意表达、能接受访谈且已充分知情的真实用户。邀请页必须明确：这是内测、AI 内容有局限、可随时删除和退出。

| 批次 | 人数 | 来源/筛选 | 运营动作 |
|---|---:|---|---|
| 核心共创 | 15–20 | 熟人转介、宠物社群管理者、愿意 1:1 访谈者 | 全程陪伴，首日/第 3 日/第 7 日访谈 |
| 验证组 | 30–50 | 宠物纪念、领养、内容创作等相关社群 | 邀请码分批发放；收集关键漏斗与问题 |
| 扩展组 | 至 100 | 由前两组自然分享带入 | 只在核心指标/审核能力稳定后开放 |

不得用“治愈悲伤”“让它复活”“不来它会难过”等话术拉新；不得以用户的哀伤或私人素材做定向营销。

### 5.2 用户旅程运营触点

| 节点 | 用户需要 | 运营内容 | 禁止事项 |
|---|---|---|---|
| 首次浏览 | 先理解产品是否安全、是否适合自己 | 安静展示一扇窗；单一 CTA “想为它留一处” | 登录墙、倒计时、夸张承诺 |
| 建档中断 | 不确定素材如何使用 | 简短说明“可跳过、可稍后补、可删除” | 催促补全、情绪施压 |
| 首日回访 | 看见有价值的新内容 | 一条克制的近况，允许关闭/反馈 | 高频推送、假装宠物真实存在 |
| D3/D7 | 愿意继续或愿意退出 | 轻量邀请说说体验；必要时提供暂停入口 | 用“它在等你”召回 |
| 分享 | 想让别人理解自己 | 默认私密、用户主动开启可见性后才生成窗口 | 自动公开、展示热度/排行 |

### 5.3 每日运营节奏

- 上午：查看错误、审核队列、AI 异常和前一日漏斗；P0 级问题当天升级。
- 下午：处理用户反馈与访谈；把重复问题归入“认知/流程/内容/技术/合规”之一。
- 晚间：只观察不打扰；敏感时段不做召回触达。
- 每周：产品、研发、QA、运营、法务 30 分钟发布例会，按“门禁、数据、风险、决策”四项输出纪要。

## 7. 复盘框架与下一阶段决策

P0 两周结束后只回答四个问题：

1. 用户是否理解“回声”是温柔的纪念陪伴，而非承诺真实复现？
2. 建档和首日回访是否各自形成了明确价值，还是存在显著流失点？
3. D1/D7 回访是否由内容价值驱动，而不是由打扰或愧疚驱动？
4. 分享是否自然发生，且没有因公开、文案或审核带来信任风险？

决策规则：

- 若安全/合规/内容问题出现 P0 事故：停止放量，先修复和复测。
- 若建档完成低、但回访和访谈评价好：优先缩短或分段建档，不扩社交功能。
- 若建档好、D1 回访低：优先提升首条回声质量与到达机制，不做付费。
- 若留存成立、分享弱：优化“私密默认下的主动分享”表达和窗口承接，不增加排行榜或激励。
- 只有在 P0 指标、审核能力与合规准备同时稳定后，才进入 P1 公测及订阅/增值服务的验证。
