# 内容运营台体系

状态：现行 · 2026-09-17
依据：`SPEC-admin-console` M3 / M7 开关；`API-CONTRACT` §17；`SPEC-publish-and-ops` §2
执行：`docs/handoff/ops-content-console.md`

## 概述

- 七单元里还没合上的后台，只做**内容运营闭环**，不是整份管理后台。看板、客服、收入、TOTP、独立 `echo-admin` 仍后置。
- 一套台、两种对象、一个开关。作品与回忆卡分表分队列，不能拿 Work id 写进卡工单。入口 `?ops=`，后台是后台，不套 C 端手机壳。
- 作者侧已有：墙状态、「看看为什么」、一生一次申诉。运营台壳、回忆卡待审/申诉、开关读写已合。
- 作品已公开可下架、再上架不改 `reviewedAt`。回忆卡已公开可下架；下架后运营不能直接恢复，只能等作者申诉。
- 举报只读端点在，C 端提交规格未定。台里标「未开」，不装假处置。
- 整改只对这套台提，不再按「多一个 tab」开账本。
- 不做：漫画/视频、真短信、打 Tag、占 5180/18080、两份锁住夹具、`originType` 编辑、申诉次数、原图下载。

## 这套台是什么

公开层能审、能下架、能留痕，才算 B04 闭环。规格里的完整后台（M1–M8）是另一件事。

```text
作者投稿 / 出卡
    → 待审
    → 通过（公开，reviewedAt 只写一次）或 先不公开
    → 可申诉一次（appealAt 只写一次，推翻不退还）
    → 已公开可下架
    → 作品可再上架（不改 reviewedAt）；回忆卡不能直接恢复
配置：先审后发 / 先发后审（主管，无需发版）
```

| 栏 | 对象 | 接口 | 2026-09-17 代码事实 |
|---|---|---|---|
| 作品 | `t_work` + `t_work_moderation` | `?targetType=work`；`tab` 空/appealing/public/takendown | C 端墙 + `?ops=works` 四栏已合 |
| 回忆卡 | `t_memory_card` + `t_moderation` | 默认队列 `tab=pending\|blocked\|appealing\|handled` | 待审/申诉/已处置已合；已公开可下架，无再上架 |
| 开关 | `t_moderation_setting` | `GET` + `PATCH /admin/moderation/settings` | GET 须先于 `:id`；台里可读可切 |
| 举报 | `t_report` 读取 | `GET /admin/reports` | 只读在；提交规格未定 → 未开 |

角色仍是 `ECHO_ADMIN_ROLES`：只读 / 审核员 / 主管。没列入一律 403，不是默认放行。

## 整改（按序，同一账本）

| # | 改什么 | 完成样子 |
|---|---|---|
| R0 | 壳 | `?ops=` 一桌：作品 / 回忆卡 / 开关 / 举报(未开)。不套 PhoneFrame。403/空/加载说清。`?ops=works` 仍进作品栏 |
| R1 | 回忆卡 | 待审通过或先不公开；申诉维持或回待审。`originType` 只读。申诉只显示是否已申 |
| R2 | 开关 | GET 当前档，主管可切先审/先发 |
| R3 | 回忆卡下架 | 已处置栏里公开卡可「先收起来」；下架后不出现再上架。状态机仍只认作者申诉 |
| R4 | SLA 展示 | 只信服务端 `slaBreached`。真则写「已超时」。前端不算时差、不读时钟 |
| — | 举报 | 规格未定提交端，本轮不装处置 |
| — | M1–M8 其余 | 后置，不从这套台长出去 |

## 红线

- 后台数字不回流 C 端。
- 审核不改 `originType`，界面不给编辑。
- 申诉不是次数。
- 处置带服务端 CAS；前端不自算 SLA。
- 先审/先发只影响新内容，不翻历史。
