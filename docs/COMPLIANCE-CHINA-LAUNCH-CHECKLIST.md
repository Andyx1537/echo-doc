# Echo 中国大陆上线合规与审批清单（运营牵头版）

| 项 | 结论 |
|---|---|
| 适用产品 | 公开回忆瀑布流（共鸣厅）+ 用户发布/互动 + 推荐 + 订阅付费 + 图片、肖像、声音与可能的 AI 整理/生成；被牵挂的亲友/宠物（阔别、久离、以及已经离开的）的上传与记录是其中一类用户自主记录场景 |
| ⚠️ 合规口径变化（2026-08-25） | 产品对象范围已由“故去之人/物”扩展为“阔别、久离、牵挂之人/物”（`COPY-GUIDE.md §1.0`）。**合规上的直接后果**：对象**在世**的比例将显著上升，肖像/声音的授权主体从“近亲属”变成“**本人**”，`§1 B` 相应行已并入在世对象边界条款。**纪念仍是我们承接的子场景之一，不再是品类自称**（层级关系见 `COPY-GUIDE.md §2.5 ④`），对外品类表述据此调整。 |
| 结论 | **不是只做 ICP 备案。** Echo 应按「UGC 内容社区 + 推荐服务 + 付费数字服务 + 涉及敏感个人信息/AI 的平台」准备。 |
| 上线建议 | 首发限定为：图文回忆、实名后发布、作者可控公开范围、人工审核+投诉、非个性化推荐；视频/直播、公开人像生成、跨境 AI 调用均不作为首发能力。 |
| 本文性质 | 运营/产品/技术的项目清单，不代替持牌律师、通信管理局、网信及公安机关的正式意见。涉及牌照、数据出境、AI 公共服务时，必须在提审前取得专项法律意见。 |

| **AI 写作、图片美化、人物/声音生成** | 生成式 AI、深度合成、AI 标识 | AI 产物显式标识 + 隐式元数据标识；用户上传/发布时提供 AI 内容声明；对肖像、声音等敏感信息单独告知与单独同意；禁止拿用户原图/声音训练，除非单独、可撤回的 opt-in；AI 服务商、模型、素材流向可追溯。 |
| **人像与亲友相关内容（🔴 在世 / 已故两类，授权主体不同）** | 个人信息保护、肖像/名誉等民事权利（《民法典》第 994、1018、1019、1023 条） | 上传者须确认其拥有发布及处理权；涉及在世第三人、未成年人、声音/人脸的内容单列提示；提供快速投诉、遮蔽、下架和人工复核。不得把“纪念”误导成现实身份背书或死者意志表达。<br>🔴 **在世对象边界（`COPY-GUIDE.md §2.7` 的落地条款载体，2026-08-25 并入本行）**：对象**在世**时，平台**不得**以其口吻生成“近况/来信/消息”，**不得**做拟真肖像生成或声音克隆。**依据**：在世者的肖像权、声音权属**本人**（第 1018、1019、1023 条），上传者 A **无权代 B 授权**——这不是“风险偏高”，是**没有合法授权基础**，§3.3 那句“我确认已获得必要授权”的权利承诺**兜不住它**。逝者场景可走“近亲属同意”（第 994 条），该路径**不可类推到在世对象**。<br>**技术落点**：对象状态（`unknown` / `deceased` / `living`）须随内容与 AI 调用**显式携带**，缺字段按 `unknown` 走最保守分支，不许由模型推断；放开的前置条件是“取得对象本人可验证同意”的机制，不是“基调已经放宽”。 |
| **视频、直播、音频社区** | 网络视听、内容安全的额外监管风险 | 首发不启用公开视频/直播。后续启用前先取得专项意见，核验是否触发网络视听节目服务、音乐版权等要求；不能把图文社区的审核能力直接套到直播。 |
| **海外模型/云/API** | 个人信息出境 | 原始照片、面孔、声音、回忆文本不得默认传到境外。优先选中国境内可合规签约的云与模型；确需出境时，按个人信息出境路径、单独告知/同意及合同/评估要求另行落地。 |

## 2. ICP、App 备案、ICP 许可证：不要混为一件事

1. **域名 ICP 备案**：非经营性互联网信息服务的基础备案。使用中国大陆服务器的官网、H5、API 域名通常都要先做。
2. **App 备案**：移动应用提供互联网信息服务的备案，不能用“网站已备案”替代。Echo 正式面向境内用户提供服务前应完成。
3. **ICP 增值电信业务经营许可证（通常称 ICP 许可证）**：不是所有 App 都当然需要；但 Echo 若以自营订阅/增值服务持续收费提供信息服务，存在被认定为经营性互联网信息服务的较高可能。**项目应把“上线收费前取得/确认该许可证路径”作为默认计划，而不是事后补救。**
4. **前置审批**：Echo 的基础图文回忆社区通常不应主动触发新闻、网络出版、网络视听等前置审批；这是产品边界，不是天然豁免。只要加入新闻聚合、长视频/直播、数字出版物等功能，重新核验。

> 运营纪律：Echo 可以表达“为想念留一处位置”“上传、整理与缅怀重要的人或宠物”，但不将自己定义为网络墓园。不要在官网或广告中承诺“永久云存储”“官方网络墓园”“线上陵园”“代祭/殡葬服务”“情感治疗”。这些表述会把产品从“回忆社区”推向额外的监管、消费者与医疗/殡葬风险。

> ### 🆕 🔴 口径合并：「冻结永久保存类营销承诺」与「不因长期未登录删除」不是一回事（2026-08-25）
>
> ⚠️ 🔴 **这两句话并排读会互相削弱，必须合并成一个口径，否则运营与文案会在两条之间来回摇摆：**
>
> | | 本清单的「冻结**永久保存**类营销承诺」 | `DECISIONS CM-D19`「**永不采用**长期未登录即删除，且要当差异化优势说」 |
> |---|---|---|
> | 约束的是 | 🔴 **一句承诺的<u>时间跨度</u>** —— 「永久」是一个我们**无法履约**的期限 | 🔴 **一条**<u>删除规则</u>**的有无** —— 我们**不设**「长期不登录就清号」这条规则 |
> | 为什么 | 平台自身的存续期不可预期；承诺「永久」在《消保法》与《民法典》496–498 项下是**可能无法履行的格式条款** | 长期未登录**恰恰是丧亲用户的常态**——他打不开这个 App，不代表他不要那些照片。🔴 **拿「清理不活跃账号」的通行做法套在这个产品上，删掉的正是最珍贵的那一批** |
>
> 🔴 **合并后的唯一口径（对外照这个说）：**
>
> > **我们不会因为你很久没来就删掉它。**
>
> **三条执行细则：**
>
> 1. 🔴 **不用「永久」二字**（既有纪律，本次合并**不把它写回来**）。⚠️ **同样不用的还有**：「**永远**保存」「**终身**保存」「**一辈子**都在」—— 🔴 **换个词不换意思，等于没改**。判据不是有没有出现「永久」这个字，是**这句话承诺了一个我们无法保证的期限没有**。
> 2. ✅ **可以说、而且应该大方说的**：「不因长期未登录而删除」。🔴 **这是一句可履约的承诺** —— 它约束的是**我们不做某个动作**，而不是保证某个期限。`CM-D19` 要求把它当差异化优势说，**与第 1 条不冲突**。
> 3. 🔴 **说法必须与用户协议同源**（`COPY-GUIDE §2.8`）。⚠️ **本条特别容易翻车**：它是一句**很好用的营销话术**，一旦客服或活动页把它说成「你的回忆永远都在」，🔴 **依《民法典》第 498 条，那句更宽的表述可能<u>压过</u>协议里那条更窄的承诺。**
>
> ⚠️ 📋 **一个已登记的未决问题**：「不因长期未登录而删除」一旦写进协议，🔴 **它就是一项无限期的存储义务**；将来若确需调整，能否调整、怎么调整，须先有法律路径 —— 见 `SPEC-trust-and-compliance §CM-G8.3 LW-6`。🔴 **这不影响现在照上面的口径说**，但决定这句话在**协议里**写到多硬。

## 3. Echo P0 应该怎么设计，才能既能上线又保留产品灵魂

### 3.1 首发产品边界（建议确定为上线裁定）

| 可以首发 | 暂缓/关闭 | 原因 |
|---|---|---|
| 图文回忆集、公开/仅自己/凭链接可见、记得、献花、有限字数的回声、作者审核与关闭互动 | 公开长视频、直播、语音房、陌生人私信、同城、热搜榜 | 把审核、未成年人、人身安全及视听风险控制在可运营范围内 |
| 编辑精选的瀑布流、主题页、时间排序 | 纯黑箱“为你推荐”、激励用户停留的悲伤内容放大 | Echo 的差异应是“被看见但不被消费”，并降低算法备案及舆情风险 |
| AI 辅助润色（默认不开）、相册整理（用户主动触发） | 人脸复刻、声音复刻、逝者对话、用用户素材训练公共模型 | 后者的肖像、人格、深度合成和心理伤害风险明显更高 |
| 订阅：更长保存、更高级编排、导出、私密协作、展示模板 | 将“看见回忆”或基础发布、基础互动锁进付费墙 | 免费层保证社区有内容和共鸣；付费买的是更可靠、更有仪式感的保存与呈现 |

### 3.2 发布与互动的必要流程

```text
录入回忆 → 作者选择可见范围 → 风险提示/权利确认 → 内容审核 →
进入共鸣厅（仅“公开”）→ 他人记得/献花/回声 → 作者可见、可关闭、可处理 → 举报/申诉/运营复核
```

必须写进产品验收的规则：

- 默认私密；用户主动选择“公开”才进入瀑布流。公开页清楚提示“会被陌生用户看到、可能被搜索/分享”。
- 对“在世人物照片/声音、未成年人、他人隐私、逝者身份信息”设二次确认；不要求用户上传复杂证明，但必须有权利承诺、投诉入口和优先人工处理队列。🔴 二次确认解决的是**上传与展示**；**在世对象的 AI 拟真与代言不在二次确认能放行的范围内**（见 §1 B「人像与亲友相关内容」行）。
- 回声应为多维但有限的互动（如“我也记得”“留一束花”“同一段青春”“想听更多”“安静陪伴”），并保留文字回声。运营不以悲伤强度或冲突度作为推荐信号。
- 删除、撤回、封禁、投诉、审核结论均留审计记录；面向用户的可见层即时失效。现有软删、授权账本与 AI 溯源规范可继续作为工程基线。

### 3.3 个人信息与 AI 的红线

- 人脸、声纹、医疗/哀伤经历、精准位置、关系网络都可能构成敏感个人信息或高敏感场景。收集必须有明确目的、最小范围、单独同意和更严格保护。
- “上传的是别人”不等于平台无责任。发布页增加：**“我确认已获得相关自然人（或其监护人）的必要授权，或依法具有发布权利。”**
- AI 美化/合成图片需显示“AI 生成/编辑”标识；保存原始的生成溯源记录。若对人脸、声音进行编辑，须通知并取得被编辑者单独同意。🔴 **对在世第三人：无法取得本人单独同意时，不只是“不公开”，是根本不生成**——私域可见同样不成立（拟真化肖像/声音克隆、以 ta 的口吻发消息，均属无授权处理，见 §1 B「人像与亲友相关内容」行与 `COPY-GUIDE.md §2.7`）。
- 训练授权与服务必需授权分开：默认不训练；撤回后停止新的训练/引用。数据使用链路要能关联源素材、授权记录、生成物和模型供应商。

## 4. 项目要准备的材料包（不是临上架才写）

## 6. 运营在合法化中的职责（不是把事情推给产品）

运营是 Echo 的“内容责任人”和“承诺守门人”：

- 所有投放文案、达人素材、种子内容先过版权、肖像、音乐、AI 标识、悲伤诱导五项检查。不能从抖音/小红书直接搬运高赞内容当种子素材，必须取得授权或使用自制/可商用授权素材。
- 共鸣厅的精选不是“谁最惨谁靠前”。建立人工选题库：青春、旧物、宠物、城市、家人、师友、重新开始；每期保证温暖、好奇、轻松与纪念内容的平衡。
- 设“高风险纪念内容”优先队列：自伤他伤、未成年、真实人脸争议、诽谤、死亡事故、身份冒用。明确谁在几分钟内接手、谁有下架权限、何时通知法务/公安。
- 售卖的是更完整的保存、整理、呈现和陪伴服务，不售卖“让逝者复活/替逝者说话”的暗示。订阅到期、退款、数据导出用简单而不惊吓的文字说清楚。

## 8. 需要负责人确认的三件事

1. 首发是否**明确不含**公开视频/直播、陌生人私信、在世第三方人像/声音复刻、海外 AI 处理？这决定合规工作量和上线日期。
2. 198/998 是否在首发就实际收款？若是，立即启动经营性 ICP 许可证专项核验，并冻结“永久保存”等可能无法履约的营销承诺。
   > 🆕 ⚠️ **两处口径已于 2026-08-25 合并，见 §2 末的合并框。** 🔴 **「冻结永久保存类承诺」与 `CM-D19`「不因长期未登录删除、且当差异化优势说」不矛盾** —— 前者禁的是**无法履约的期限**，后者承诺的是**我们不做某个动作**。对外统一说：**「我们不会因为你很久没来就删掉它。」**
   > ⚠️ **另注**：档位名称已按 `NM1` 全部改为「一档 / 二档 / 三档」，🔴 **且 `NM2` 已把 ¥998 定为「高档位占位、定价待定」** —— 本行的「198/998」应读作**收费与否**这件事本身，不是两个已定价格。
3. 共鸣厅是否使用个性化推荐？若是，推荐策略、用户关闭入口、算法备案/安全评估必须与功能同批上线；若否，首发采用编辑精选+主题/时间排序。
