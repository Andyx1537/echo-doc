### 0.4 🔴 已经做完的止血（不等命名结论）

✅ **`GTM4` 与 `§0.1` 概述两处已就地写死**（提交 `4b9cfc6`）：北极星那一句的「回声」**= 乙义**，并写明**两义正好落在这个比率的两边** —— 🔴 **AI 近况在<u>分母</u>（它是一张被发布的卡），别人的回应在<u>分子</u>**。

🔴 **写死时给了一条可自查的判据**：**分子只能由<u>别人</u>的动作产生；凡是我们自己生成就能增加的东西，一律不是分子。**

🟢 **分子的技术真源已核实**：`t_resonance_type.countsToAcceptance` 列（`schema.sql:559`），🔴 **schema 注释明写它是「什么算被接住」的唯一真源**，四处聚合（北极星 / 深共鸣率 / 零回应卡占比 / 冷启动毕业判定）读同一列。**所以乙义这一侧本来就是可精确求值的，歧义只在文字层。**

## 2. 甲义今天的真实身份（🔴 回代码核实）

### 2.1 它是 `t_memory_card` 的一个 `sourceType`

`schema.sql:425` 逐字：

```
"sourceType"  varchar(16)  NOT NULL DEFAULT '',       -- record | book_page | postcard | echo
"sourceRef"   varchar(64)  NOT NULL DEFAULT '',       -- 原素材引用 id
```

同一枚举在 `API-CONTRACT:219`（`record｜book_page｜postcard｜echo`）与 `SPEC-publish-and-ops:79` 各出现一次，**三处一致**。

🟢 **所以制作人的提法成立**：甲义在数据层就是**卡的一种来源**，与手写 `record`、生命之书 `book_page`、明信片 `postcard` **平级**，🔴 **不是一个平行于「回声」的独立品类**。这与 `OM2`「卡表装所有可发布的回忆」完全自洽 —— **甲义本来就在卡表里。**

### 2.2 ⚠️ 但 `sourceType` 只描述它落库成什么

🔴 **另有两样东西挂在甲义上，`sourceType` 覆盖不到**：

| 面 | 内容 | 出处 |
|---|---|---|
| **投递机制** | 到达式推送 + 进消息中心 + 轻通知；「初见回声不立刻甩图」，先温柔过场再以「它给你捎来第一条消息」到达 | `PRD-echo-pet §3.9`/`:56`/`:251` |
| **频率调控** | 首周 3·5·7 基线、稳定期**只降不升**（`DP11`）、温度驱动、纪念日限时不补 | `PRD-echo-pet §3.11`/`:141`/`:97` |

🔴 **对命名的直接影响**：甲义**需要名字的位置比一个枚举值多** —— 至少还有推送文案、设置项（现文案「这周先不要来信」「只保留回忆，不生成回声」）、以及订阅权益里对「已交付产出」的称呼（`CR-M②`）。⚠️ **只改 `sourceType` 的字面不叫改完。**

### 2.3 乙义在数据层是什么

🔴 **乙义不是一张卡，是一条互动记录**：`t_resonance` + 字典表 `t_resonance_type`（`schema.sql:547`–`568`）。

字典表的 schema 注释逐字写着两件要紧的事：

- **「回声类型会增加（`R7`「关注 ta」就是新增的一类）」** —— 🔴 **所以在数据层，「回声」= 一次互动，`R1`–`R7` 是它的类型。**
- **`countsToAcceptance`**：🔴 **「直接决定北极星分子，是『什么算被接住』的唯一真源」**，且**「无默认值：新增类型必须显式表态，漏写则报错」**。

🟢 **这条注释顺带证明了一件好事**：乙义那一侧**在数据层从来没有歧义**，`countsToAcceptance` 是可精确求值的。⚠️ 🔴 **歧义完全在文字层** —— 也就是说，**`GTM4` 那句话的问题不是口径没定，是那句话没说清它引用的是已经定好的哪一列。**

## 4. 命名候选与代价（🔴 不推荐，供裁定）

> 🔴 **三条评价维度按交办**：① **出现位置**（用户可见 / 只在内部）② **有没有再撞词**（已实测计数）③ 🔴 **有没有把「这是 AI 生成的」说明白** —— `IL3` 是当前默认档位，要求**以显著方式**做事实性 AI 披露（`SPEC-intervention-levels §7`）。
>
> ⚠️ 🔴 **一条判名字的纪律，照 `SR-D20` 的形式**：**判一个名字，看它让用户相信什么，不看它对我们来说顺不顺口。** 🔴 **名字本身不能替代 `IL3` 的披露**（披露是独立义务，任何名字都免不掉它）；**但名字可以<u>拆</u>披露的台** —— 一个暗示「真的是它在说话」的名字，会让旁边那句「这是 AI 生成的」显得像免责声明而不是事实。
