## 1. 已确认的产品前提（不再讨论）

1. **首页就是瀑布页（共鸣厅）**。游客进入产品先看公开、审核后的回忆窗口；这是理解产品、产生共鸣和自然转化的入口。
2. **进入录入页本身代表用户主动选择开始建立回忆集。** 不要求在录入页再次设置“要不要开始”，也不应把上传/录入设计成被动索取隐私；用户可以按流程逐步完成。
3. **回忆集、档案、记录、个人观测均属于个人用户自己的视野。** 本期不以复杂的“记忆库/档案/窗口四层”作为用户理解模型；用户只需理解“我的它 / 我的回忆”。
4. **所有用户都在看回忆；回声由其他用户的共享与共鸣产生。** 回声不是平台对单个用户主动虚构的一封“宠物来信”，也不应作为单人召回或留存施压工具。
5. **“记得”是对一段回忆最基础的共鸣标识。** 它不等于点赞、热度或排名。
6. **献花可调整为更符合理念的描述。** 保留其轻互动价值，但须去掉对象混乱与游戏化语言。
7. **定妆/识别的可靠性需要通过 LLM 与真实模型的联合测试来建立预期。** 不能只靠 mock 表现判断，也不能以“演示能跑”替代质量门禁。

---

## 2. 需要立即调整的实际产品路由

### 2.1 当前问题

H5 当前启动逻辑在新游客没有宠物时直接跳入 onboarding；这与“首页是瀑布页”的产品前提冲突，也使用户无法先理解别人如何留下回忆。

### 2.2 目标路由

```text
首次打开 / 游客
  → 共鸣厅（瀑布页）
      → 打开一扇窗，看一段回忆
          → 「我也想为 ta 留一处」
              → 进入建档 / 回忆集录入
                  → 完成后进入「我的它」

已有个人回忆集的用户
  → 默认进入「我的它」或记住上次停留页
  → 共鸣厅仍作为底部一级页签
```

### 2.3 首屏运营目标

首页瀑布不是为了追求无限浏览，而是完成三件事：

| 首页动作 | 用户应得到的理解 | 对应转化 |
|---|---|---|
| 看见一段具体回忆 | “原来可以这样留下它” | 对产品建立认知 |
| 轻点“记得” | “我能安静地回应一段陪伴” | 体验共鸣互动 |
| 点“我也想留一处” | “这是为我的它建立回忆集” | 主动进入录入流程 |

瀑布排序建议：**编辑审核的优质样本 + 与用户显式兴趣/停留相关的回忆主题**。不展示播放数、热度、记得数或“最受欢迎”。

## 3. 回声的正确逻辑：共鸣发生后的关系回响

### 3.1 定义

**回声 = 因另一位用户已共享的回忆与你产生共鸣后，留在双方可感知范围内的一种轻回响。**

它可以是：

- 对方留下的一段回忆被你“记得”后，在你的共鸣轨迹里留下一点光；
- 你与某段回忆产生连接后，获得继续看同主题/同气质回忆的入口；
- 在双方均允许的前提下，出现一句克制的“有人也记得这样的瞬间”。

它不应是：

- 平台代替宠物说话；
- 系统凭空生成“它今天在做什么”；
- 以“它在等你”之类的文案让用户回访；
- 未经他人共享或许可就基于其素材生成内容。

### 3.2 P0 可落地的最小回声

| 触发 | 呈现 | 用户可做 | 不做什么 |
|---|---|---|---|
| 用户点“记得” | 当前窗口出现暖光反馈 | 取消、继续浏览 | 不显示总人数/排名 |
| 同一用户多次主动查看相似回忆 | 共鸣厅出现一张“也许你愿意看看”的回忆卡 | 打开或略过 | 不自动播放、不推送打扰 |
| 被记得的窗口 owner 查看个人视野 | 看到“有人记得这段回忆”的匿名暖光 | 选择是否允许后续共鸣提醒 | 默认不展示访客身份或精确数 |
| 双方明确允许（P1） | 形成“共鸣记录” | 关注这段回忆/留一句话 | 不自动建立好友关系 |

### 3.3 需要产品确认的边界

- P0 的“回声”是否仅等于**暖光 + 共鸣推荐**，不出现任何 AI 生成文本？
- P1 是否允许基于已共享、已审核的文本，用 LLM 做**摘要/主题归纳**，而不是替宠物发言？
- owner 是否可以在个人设置中关闭“被记得后出现在他人共鸣推荐中”？（建议默认开、明确可关）

## 4. 个人视野：保持简单，但把“观测”做成有用的回馈

用户侧不展示复杂数据层，也不要求理解分享副本。个人视野只有三个自然问题：

| 用户想知道什么 | 产品页 | 内容 |
|---|---|---|
| 我为它留下了什么？ | 我的它 / 生命之书 | 回忆、照片、记录、时间线 |
| 哪些人也懂这个瞬间？ | 被记得的回响 | 暖光、经允许的共鸣片段；不显示竞争数字 |
| 我想继续留下什么？ | 留一笔 / 补一段回忆 | 文字、照片、语音、时间标签 |

运营侧可观测的数据与用户侧严格分开：运营看建档转化、回忆保存、共鸣触发、举报/退出；用户看自己获得的回响，不看增长指标。

## 5. 互动文案与行为调整

| 当前表达/行为 | 问题 | 建议定稿 |
|---|---|---|
| “我记得它” | 正确，保留 | 点击后：“你也记住了这个瞬间”或“你的暖光落在这里” |
| “记得它的人，聚成了一片暖光” | 可保留，但不出现人数 | 首次用一句短说明解释暖光代表“有人也记得” |
| “献一朵花” + “花是给主人的” + “你为它献过…” | 对象不一致 | 对外统一为“留一束心意”；反馈：“你为这段回忆留下一束心意” |
| AI 宠物近况 | 与共鸣回声逻辑冲突 | P0 移出主流程；若未来保留，单列为个人创作功能并明确非事实 |
| “为你的它，也建一扇窗” | 方向正确 | 保留，但落到“建立我的回忆集”，而非默认公开窗口 |

## 6. 定妆/LLM 可靠性：需要单列验收，而不是靠感觉

### 6.1 问题说明

本地 mock 试用中出现了“上传图后固定识别为狗狗、定妆候选与输入语义不一致”的演示失真。它不能证明真实模型会失败，但证明当前演示环境无法建立用户对模型能力的正确预期。

### 6.2 两段式质量策略

| 阶段 | 目标 | 实施 | 门禁 |
|---|---|---|---|
| 模拟态 | 不夸大能力、不误导体验 | mock 明示“示意效果”；使用与宠物一致的示例资产；不把固定返回称作 AI 识别 | 演示中不存在物种/形象明显错配 |
| 真实模型灰度 | 验证准确、克制与稳定性 | 选择 LLM/视觉供应商；建立脱敏测试集；人工标注物种、显著特征、禁用叙事；记录失败类型 | 物种确认率、用户“像不像”评价、内容安全率达到门槛 |

### 6.3 建议新增验收用例

- **TC-AI-01：物种不确定时不强断言。** 返回“我还不太确定，想自己选一下吗？”而非固定物种。
- **TC-AI-02：定妆候选与已确认物种一致。** 用户可选“都不像，先保留原图”。
- **TC-AI-03：回声来源合规。** 每条回声可追溯到对方已经共享且允许用于共鸣的回忆类型。
- **TC-AI-04：不制造事实。** 不出现宠物仍在现实中活动、等待用户等表述。
- **TC-AI-05：可解释失败。** 模型失败时回落为普通回忆卡，不阻断建档。
