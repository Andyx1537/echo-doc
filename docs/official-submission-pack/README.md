# Echo 对公审核与备案材料包（填报底稿）

## 0. 使用边界

这是一套给 **法务、运营、技术、行政** 协同填写的底稿，不是政府机关制式文件，也不代表已获任何审批。提交前必须：

1. 用运营主体的真实名称、统一社会信用代码、地址、负责人及联系方式替换全部 `【待填写】`；
2. 由法务根据接入商、属地通信管理局、公安网安及网信部门当期系统字段和模板复核；
3. 只在有权主体审核通过后签字、盖章和提交；
4. 不在材料中承诺无法履行的“永久保存”“网络墓园”“代祭/殡葬服务”“逝者复活/对话”等能力。

**产品定位统一写法**：

> Echo 是面向用户的回忆记录与共鸣社区。用户可自主上传、整理、私密保存或公开分享与亲友、宠物、成长经历、旧物、城市等有关的图文记忆；对故去亲友或宠物的缅怀，是其中一类用户自主记录场景。平台不提供殡葬、代祭、线下撮合服务，也不以“网络墓园/线上陵园”作为产品定位。

## 2. 还需准备的原件或外部文件

- 营业执照副本（加盖公章扫描件）、法定代表人/负责人身份证明（按渠道最小化提供）；
- 域名证书、域名实名信息、云服务/接入服务合同或控制台截图、服务器 IP/地域清单；
- 网站 ICP 备案号（如已完成）、App 名称/包名/版本号/图标/下载页；
- 隐私政策、用户服务协议、社区公约、未成年人规则、订阅与自动续费规则的最终发布链接；
- 网络拓扑、数据流图、系统清单、权限矩阵、日志/备份/漏洞修复证据（等保与公安备案使用）；
- 真实审核后台截图：审核、举报、下架、封禁、申诉、操作日志；
- 应急联系人 24 小时电话和值班表；
- 若收费：支付服务商协议、价格页、自动续费提示、退款/取消/订单截图；
- 若用 AI：模型/云服务协议、数据处理协议、AI 标识截图、授权账本和投诉机制说明；
- 若用个性化推荐：算法逻辑、数据项、关闭入口、人工干预与风险处置说明。

## 3. 顺序与负责人

1. 行政/法务填完 `01`，技术核对域名、服务器、包名。
2. 技术向接入商确认 **网站 ICP + App 备案** 的本省实际字段与附件，依据 `02` 在线提交。
3. 运营、技术、法务共同完成 `03`–`06`，并让产品实际具备材料中的能力；不能“文档有、功能没有”。
4. 安全牵头按属地要求推进公安联网备案、等保定级/备案/测评。
5. 首发若收费，法务先闭环经营性 ICP 许可证适用性；若启用个性化推荐/公众 AI，再完成 `07` 的备案与安全评估路径。
6. 最后依据 `08` 提交应用商店，商店描述、隐私政策与真实功能必须一致。

## 4. 必须由负责人确认的开关

- 首发是否收费（198/998 是否真实扣款）；
- 首发是否开启个性化推荐；
- 首发是否对公众开放 AI 文本/图片生成、人像/声音编辑；
- 首发是否开放视频、直播、陌生人私信；
- 云、对象存储、审核、AI 模型是否全部在中国境内处理。
