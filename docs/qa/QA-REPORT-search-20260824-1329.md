- **复现**：搜任意能命中主题的词（如「末班」）→ 出现「主题」分区 → 该分区**只有标题，无「查看全部」**；「记忆 / 窗口」「用户」两区在超 3 条时都有。
- **影响面**：极小。当前运营配置只有 6 个题材词，且它们之间无公共子串，**主题命中数恒 ≤3**，按钮本就不可达；未来热门词扩容到 4 个以上共前缀词时才会显现。
- **文件**：`echo-h5-proto/src/components/SearchScreen.tsx:434-451`（主题分区 `s-section-head` 内只渲染标题，无 `s-viewall-link`）
- **引用定案**：附录 A.3「三个分区（各最多 3 条 + 「查看全部 →」）」；同节「查看全部去向：主题→复用广场按 category 过滤」
- **规格张力（交 PM 裁定）**：A.3 既要求三区都有「查看全部」，又把主题的去向定义为「复用广场 category 过滤」——而**点单个题材 chip 本身已经就是这个去向**，一个分区级「查看全部」没有明确的目标 category（要按哪个题材聚合？）。建议 PM 二选一：①明确主题区**不设**「查看全部」（把 A.3 该处措辞收敛为「记忆/用户两区」）；②定义主题区「查看全部」去向（如进题材总览列表）后再派实现。
- **建议**：**先由 PM 裁定规格，再决定是否改代码**；QA 不建议在语义未定前硬加按钮。

### M-2（Minor）「分类」命中时看不到高亮，用户不知道为什么这条被搜出来
- **复现**：搜「宠物」或「校园」→ 记忆区确实给出正确结果（豆豆/毛球/团团、靠窗第三排的风扇…），但页面上**没有任何高亮**；因为命中的是窗口的**分类中文标签**（宠物 / 校园），而分类**没有渲染在结果卡上**，所以无处可高亮。
- **影响面**：小。结果正确、可点、可跳转，只是「为什么命中」对用户不透明，弱化了高亮的解释作用。
- **文件**：
  - `echo-h5-proto/src/api/searchLogic.ts:60-73`（`searchWindows` 把分类标签纳入匹配）
  - `echo-h5-proto/src/components/SearchScreen.tsx:63-97`（`WindowRow` 只渲染 标题/近况/作者/暖光，无分类字段）
- **引用定案**：附录 A.3「高亮：命中关键词高亮，作用字段 = 标题 / 昵称 / 近况 / 分类」 vs. 同节「结果卡字段白名单：缩略图 + 标题 + 作者 + 暖光质性描述」
- **规格张力（交 PM 裁定）**：**基线自身有内部张力**——要求「分类」参与高亮，但字段白名单里没有分类，两条不可同时满足。建议 PM 择一：①在结果卡补一枚**只读题材小标签**（并入白名单）以承载分类高亮；②明确「分类只参与匹配、不参与高亮」，把 A.3 高亮字段收敛为 标题/昵称/近况。
- **建议**：同 M-1，**先裁定基线，再定实现**。

### M-3（Minor · 仅开发模式）`search_open` 等事件在 dev 下重复上报一次
- **复现**：开发模式打开搜索页 → `search_open{from:"plaza"}` 打了 **2 次**（进详情时 `window_open`/`window_seen` 同样各 2 次）。
- **根因**：`React.StrictMode` 在**开发环境**会故意二次执行 effect；生产构建不会。属框架开发期行为，**非搜索页逻辑缺陷**，也非本轮改动引入。
- **影响面**：仅影响开发期 console 观感；**若未来把埋点接到真实数仓端点，需确认统计口径以生产构建为准**（dev 数据不入仓）。
- **文件**：`echo-h5-proto/src/main.tsx:7`（StrictMode）+ `src/components/SearchScreen.tsx:144-148`（`search_open` 在挂载 effect 内）
- **建议**：不改代码；在数仓接入文档里注明「dev 数据不入仓」即可。

### M-4（Minor · 观察）「查看全部」是页内视图切换，没有走 `?q=&type=` 的 URL 形态
- **复现**：点「查看全部」→ 页面内切到全量列表（顶部「← 记忆 / 窗口 ·「宠物」」），**地址栏不变**，不可分享/回退到该列表。
- **影响面**：小。**q 确实被带上**（列表按当前 q 过滤、标题回显 q），A.8「查看全部跳转带 q」的实质要求已满足；缺的只是 URL 形态。
- **根因**：原型未引入路由（全站为单 URL 状态机），非本页取巧。
- **文件**：`echo-h5-proto/src/components/SearchScreen.tsx:237-240`（`setViewAll` 状态切换）、`:320-349`（`renderViewAll`）
- **引用定案**：附录 A.3「查看全部去向：记忆→窗口列表 `?q=&type=windows`；用户→用户列表 `?q=&type=users`」
- **建议**：接真后端 / 引入路由时一并落 URL 形态；本轮 mock 阶段可接受（复签 §5.3 已认可「本轮 mock」范围）。
