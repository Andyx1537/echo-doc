## 2. 必补项清单（阻断签字 · 建议直接并入附录 A）

> 每条给出「问题 → 补充建议文字」，PM 可基本照抄进附录 A 对应小节。

### 必补-1 ★【完整度·A.5/新增 A.4bis】缺「加载态 + 失败兜底可重试」整类状态
- **问题**：附录 A 只写了清空/空格/超长，**完全没有加载态与失败态**。`SPEC §2` 通用底座明列「加载态 / 失败兜底可重试」为每页必备；真后端 `GET /search?q=` 必然有 in-flight 与失败。此为**硬缺口**，非可选。
- **补充建议**（并入 A.3/A.5）：
  - 输入联想请求在途：分区结果区显**轻量加载占位**（骨架/「正在找…」，不用转圈轰炸，守安静基调）；mock 同步可瞬时，真接口按此渲染。
  - 请求失败：**温柔兜底 + 可重试**，文案如「网络有点慢，<u>点一下再试试</u>」（过词表、给出口）；不弹硬错误弹窗。
  - 竞态：**丢弃过期响应**（只渲染最新 q 的结果），防旧响应覆盖新输入。

### 必补-2 【无歧义·A.3】「每区最多 N 条」N 未定
- **问题**：`每区最多 N 条 + 查看全部`——N 是数字未给，开发无法照做。
- **补充建议**：定死 **每区最多 3 条**（记忆/用户/主题各 3），超出走「查看全部」。（沿成熟范式；若 PM 有偏好可改，但须写死一个数）

### 必补-3 【完整度+无歧义·A.3】「查看全部 →」去向未定义
- **问题**：点「查看全部」跳到哪、什么形态完全未写。
- **补充建议**：定义为**按该分区类型 + 当前 q 的全量结果页**（如记忆区→窗口列表页 `?q=&type=windows`，用户区→用户列表页，主题区→复用广场按 category 过滤）；本轮 mock 下同样返回全量本地过滤结果。若本版暂不做独立全量页，则须**明确「查看全部」本版隐藏/置灰**，不留半截交互。

### 必补-4 【契约·A.5】真后端返回形状与 `{items}` 信封铁律口径冲突
- **问题**：A.5 写「返回 `{windows,users,topics}`，遵 `{items}` 惯例」——二者矛盾/含糊。`DECISIONS G'' QA2` 铁律：所有列表接口统一 `{items,nextCursor}` 信封、前端取 `.items`。开发不知道该套几层。
- **补充建议**：**明确三分区各自是 `{items}` 信封**，例：
  ```
  GET /search?q=  →  {
    windows: { items:[...], nextCursor },
    users:   { items:[...], nextCursor },
    topics:  { items:[...], nextCursor }
  }
  ```
  即便本轮标 TODO，也须现在把形状钉死，避免真接口返工。（对齐 `API-CONTRACT §12/§13`）

### 必补-5 【无歧义·A.5】「超长词安全截断」阈值未定
- **问题**：截断到多少字未给。
- **补充建议**：定死**最大输入长度（建议 50 字）**，超出即在输入端截断/不再接收；同时超长仍不触发异常。

### 必补-6 【完整度·A.5】埋点缺维度 + 缺关键事件
- **问题**：只列 4 个事件名，**无参数维度**；`CM-G5 事件数仓/被接住率看板`需可拆维度。且缺「热门词点击」「查看全部点击」等关键动作。
- **补充建议**：
  - 为每事件定关键属性：`search_query{q_len, has_result}`、`search_result_click{section∈记忆/用户/主题, item_id, position}`、`search_history_clear{count}`、`search_open{from}`。
  - 补事件：`search_hot_click{term}`（热门 chip）、`search_view_all{section}`（查看全部）、`search_history_click{term}` / `search_history_delete_single`。
  - **不记录任何可拼成公开榜/人数的聚合口径**（守 `D19` 停留信号仅私域）。

### 必补-7 【完整度·A.2/A.3】空区处理 + 双空态未定义
- **问题**：(a) 输入态某分区 0 命中时该区如何呈现？(b) **默认态热门也为空/运营未配** 且历史为空时显示什么？均未写。
- **补充建议**：
  - 分区无命中：**隐藏该空区标题**（同历史空块规则），只留有结果的区；三区全空才进 A.4 空结果态。
  - 双空（热门未配 + 无历史）：给**兜底默认屏温柔文案 + 单一引导**（如「输入几个字，找找那段回忆」），不留冷白（对齐 `D20` 空态铁律）。

### 必补-8 【无歧义·A.1/A.2】多处「二选一」留给开发发挥
- **问题**：A.1「全屏下往上滑入**或**整页切换」、A.2 历史「**chip 或列表**」——「或」= 开发自行发挥，违反门禁。
- **补充建议**：**各定死一种**。建议：进入=**下往上滑入**；历史=**chip 平铺**（与热门统一视觉、更省空间）。（PM 可改选，但须去掉「或」）

### 必补-9 【无歧义·A.1】`←返回` 与 `取消` 职责重复 + 输入框清空(×)交互缺
- **问题**：顶部同时有 `←返回` 和 `取消` 两个退出入口，行为差异未说明；且**输入框内的清空按钮(×)** 未定义（A.5 只说「清空输入→回未输入态」，没说怎么清空）。
- **补充建议**：
  - 明确二者关系：建议**只保留右侧「取消」= 退出回广场**；`←返回` 若保留则等同「取消」，须写明「二者行为一致」，避免开发臆测。
  - 补输入框内**清空按钮(×)**：有输入时输入框右侧显 ×，点击清空输入 → 立即回未输入态（承接 A.5）。

## 5. 可验收性（A.7 作为 L0 基线的评价）

- A.7 现有 7 条**主干可逐条判**，作为 TC-31 细化版方向正确。
- **需补验收点**（随 §2 必补项落地后加入 A.7）：
  1. **加载态**：联想在途有轻量占位、不卡死（必补-1）。
  2. **失败态**：请求失败给温柔兜底且**可重试**（必补-1）。
  3. **查看全部**：点击跳转到对应分区全量结果页且带 q（必补-3）。
  4. **埋点逐事件**：7~8 个事件名与关键属性均可触发、可核（必补-6），不改为笼统「埋点齐」。
  5. **超长/空区/双空**：截断长度可判、空区隐藏、双空有兜底屏（必补-5/7）。
- **建议拆细**：A.7 最后一条把 5 个红线塞成一条，建议**拆成逐条勾选**（无数字 / 无排名 / 不悲伤竞赛 / 历史仅本地 / 过词表），红线零容忍应逐条判定。

## 7. 最终结论

- **结论：需补齐后再签（暂不签字）**。目标方向正确、红线达标，但未到「开发照做即可」的无歧义门槛。
