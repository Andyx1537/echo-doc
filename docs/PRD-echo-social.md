## 0. 定位一句话

把 echo 的终极命题落地：**"隔得再远、离得再久，因为回声与共鸣，ta 在互联网上、在更多人心里继续存在。"**
共享不是背离这份牵挂，是把牵挂从"你一个人的私密"升维成"被更多人记得的存续"。

价值支柱（用户已选）：**陪伴 · 疗愈 · 传承** + 本层新增的**共享/共鸣**。健在宠物纳入核心扩盘（现在建档陪伴，不幸时无缝转往宠）。

> **两层和谐模型（最上位关系 · 2026-07-28 定案，见 `DECISIONS.md` G⁗）**：
> - **底·核心（私域）**="我的它"+我的记忆+**接收 AI 关怀抚慰陪伴**——情绪价值本体、留存命根，安全私密、默认不外露；
> - **皮·观光（社交）**=**共鸣厅**——留给别人轻轻看见、留下善意的地方，外向克制、**非核心回路**、开窗可选。
> - **故宠住在私域的"底"，共鸣厅只是一层可选的善意皮**；用户**永不被逼把悲伤公开表演**（化解"故宠 vs 共鸣厅"社交冲突、守"不消费悲伤"）。本层所有玩法都是这层"皮"的下游，绝不冲淡 1v1 私域主轴。

## 0.6 北极星概念：过去 → 未来 桥梁模型（统摄本层）

本层最上位的定义。献花/亲友/共同守护/接力 都是它的下游实现。

**一句话**：**过去是通往未来的桥梁——通过一起凝固确认的过去，创造活人之间未来互相认可的桥。**
我们不做一座只朝后看的墓园；它是**活人之间的连接组织**：越多人共享同一段被确认的过去，就越能在未来彼此认出。

### 记得 vs 看过（两个一等公民统计）
| 指标 | 语义 | 动作 | 可见性 | 性质 |
|---|---|---|---|---|
| **看过数** | 点开浏览过（可能没印象） | 被动：点开窗口即计 | owner 可见 | 脚印，量大、廉价、沉入背景 |
| **记得数** | 看了**有印象**、主动标记"我记得它" | 主动：一人一次的**状态**（非可叠加的量） | **对外可观测** | 誓约，量小、珍贵 |

- **记得 ≠ 献花**：献花是给 owner 的社交致意（可购买、可多献、可叠加）；记得是对"**它**"的静默誓约（一人一次的开关状态，不可叠加、不可购买）。
- **记得 ≠ 看过**：看了没印象是看过；看了有印象、愿意记住，才点"记得"。

### 沉默过程（诚实的哀伤，不对抗遗忘）
- 记得数会**自然下滑**——越来越少人记得、越来越多人去寻新伴。这是痊愈，是健康的，**不造假托住、不藏、不惩罚**。
- **记得 → 看过（曾经）** 的滑落只温柔、不指责（禁"你 30 天没来它很难过"式内疚）。
- 遗忘的残留不是失败，是**土壤**：被凝固确认的过去（回忆/性情/名场面）成为**种子**，让没见过它的新人也能共鸣（→ §1 相似匹配/领养接力）。**我们把"被记得过的过去"沤成"未来认可"的土。**

### 桥的原子单位：共同锚定（co-anchoring）（概念先落，交互归第二步）
- 两个都"记得"同一个它的人，本质是**共享过或共鸣同一段生命**的人。他们**一起确认一段过去**（双人锚定 → 该回忆升为"正典"、可信权重更高），这个确认动作本身，就把两个活人**接上了**。
- 「记得它的人彼此认出 / 共同锚定」的**完整交互放到第二步（交互）深挖**，本轮只落：**概念 + 记得/看过埋点 + 记得数对外可观测**。

### 串起三步走
| 步 | 桥的形态 |
|---|---|
| 一 · 自洽 | 私密记得（我和它）＝个体过去 |
| 二 · 交互 | 共同锚定（双人确认过去）→ 记得者彼此认出＝过去→活人桥 |
| 三 · 共鸣 | 凝固的过去成种子 → 群体共鸣 → 新人接力＝过去→未来桥 |

### 护栏
- **对外**：记得数**可观测 ≠ 排行榜/攀比**（与献花解耦同理，不做人气排名）。**对外呈现为暖光浓度 + 面孔墙（记得它的人的头像聚成一片暖光），不显精确数字、不做竞争性名次**——重"面孔/暖意"而非"数目"（定案见 §0.7）。
- **对 owner 本人（定案 2026-07-27）**：**owner 自己可见精确记得数与记得者**——这是 owner **看见"谁与自己共鸣"** 的方式（记得同一个它的人，即与你共享/共鸣同一段生命）。看过数亦仅 owner 内部可见。
- "（记得者之间）认出彼此 / 让他人看记得者列表"**需同意**，守私密珍贵感。
- 滑落只温柔、不惩罚。

## 2. 深挖玩法：「一扇窗」+ 裂变分享（本轮重点）

把私密陪伴通向共享的第一道门，也是最强的低成本裂变入口 & 回访钩子。

### 2.1 可见性：三档 + 颗粒度
- **私密（默认）/ 挚友可见 / 公开**。挚友档接"共同守护(2:1)"（见 §2.10）。
- 开放的是"**窗口**"而非全部，逐项显式勾选（默认最小开放）：
  ① 生命之书（精选）② 部分近况回声 ③ 空间一角 ④ 是否允许献花/留言 ⑤ 是否参与跨宠相遇。
- **可随时收回**；收回后分享链接立即失效。

### 2.2 窗口页（访客看到什么）
- 一个可分享的"**窗口页**"：**H5、"免登录"可看**（裂变关键——朋友点链接即看）。
  - ⚠️ 注意："免登录"是**面向用户的体验说法**，不是"没有账号"。见 §2.8：访客进来即被分配**匿名/游客账号**，走与正常用户**同一套逻辑**，只是尚未绑定。
- 页面元素：宠物名 + 一张定妆图 + 一句性情签名 + 生命之书精选时间线 + 最近一条温柔近况 + 献花计数 + "为你的它也建一扇窗"CTA。
- 基调：安静、克制、美——像一张**会呼吸的电子明信片**（视觉系 §3.14）。

### 2.3 裂变机制（温柔、不 spammy）
- **自然触发点**：建档完成"要不要让家人也看看它"、生命之书里程碑（百日/周年）生成、收到献花时。
- **分享物料**：自动生成"美"的分享卡/短动态（一图一句），适配微信/小红书等；情感内容天然易传。
- **落地页 = 窗口页 → 一键建档转化**；邀请家人成为"共同守护者"= 关系链绑定（强留存、难卸载，见 §2.10）。

### 2.4 献花机制（社交认可层 · 对"主人本人"的心意）

> **对外命名（CR4 · 2026-07-28）**：对外统一为**"留一束心意"**（不再用"献一朵花/花是给主人的"），反馈"你为这段回忆留下一束心意"；**内部字段/接口仍沿用 `flower`**，机制不变。下文"献花"为内部术语。

**定位（关键）**：花 ≠ 暖意，是两套逻辑。
- **花 = 社交层，是对"主人本人"的认可**——访客/亲友对"主人的它、那段回忆/印象"的牵挂、共情、喜欢，本质是**人对人**的心意，引申为社交。
- **花不影响宠物温度**：宠物的暖意/温度是主人 1v1 私密系统（§3.11），由主人自己照顾驱动，外部献花**不介入**（守住"社交不牵动私密主轴"红线）。宠物那套逻辑**单独深挖**。

**多维度设计（可操作空间）**
- **发起方限制**：每人每天免费 **N 朵（暂定 5，可配）**；额度内自由分配（全给一只 / 分散、给自己的/亲友的/广场陌生的/共忆墙均可）。
- **接收方不设上限**：一只宠物可被无限多人记得（不人为压"被记得"）。
- **没花可买**：免费额度用完可购买加量（变现入口），满足"愿意比别人多献"。
- **花的种类**：日常花 / 限定花（纪念日·节日）/ 高级花（付费，寓意更重、更美）。
- **表达**：具名或匿名、可附一句话、单朵→整束（数量即心意浓度）。

**可见度（红线刻度 = 稳）**
- 「记得」**对外以暖光浓度 + 面孔墙呈现，不显精确数字**（定案 §0.7）；**无花数排行、无攀比榜**。**owner 本人可见精确记得数与记得者**（看见谁与自己共鸣，定案 2026-07-27）。
- ⚠️ **2026-08-25 回改（本行原写「无粉丝数」）**：**「无粉丝数」已被推翻。** 单向关注发布者成立，**粉丝数公开且为精确数字**，🔴 **仅在作者主页 / 个体页可见**——不在共鸣厅信息流卡片上，且 🔴 **不做全站作者榜单 / 涨粉榜 / 粉丝数排行**（`DECISIONS D14` 这条不推翻），🔴 **粉丝数不进排序**（`X12`）。<br>**依据**：制作人 2026-08-24 裁定，见 `SPEC-recommendation-ranking.md §15 RK14`/`RK36`（推翻 `PRD-RESONANCE-INTERACTION-PALETTE E1`「不订阅人、不形成粉丝数」）与 `§1.5`/`§9 红线三`。**本行其余部分（记得数不显精确数字、无花数排行、无攀比榜）不受影响，继续成立**——放开的只是粉丝数这一个字段，且它的展示位置被严格限定。
- "多献=效果"体现为：对主人的**认可更浓**（束/附言）+ 献花者的**私密羁绊印记**（"你为它献过 N 朵""一直记得它的人"，主人可见的温柔名单），**不是**公开排名。

### 2.5 接闭环（为什么增强圈养）
- **献花给"主人"情感慰藉**："还有人记得/喜欢我的它" → 强共情，不改宠物温度。
- 有人献花/来看 → 推送"今天有 3 个人来看过豆豆" → 温柔回访触发（接 §3.13 闭环 ① 触发，回访钩子走"主人被认可"而非温度）。
- 窗口既是**裂变入口**，又是**回访钩子**，双向增强闭环。
- 花天然会引申社交（回赠致谢、以花为起点加亲友、纪念日集体献花→共忆墙）——但**克制**，用发起方额度收敛，不滑向庞杂社交子系统。

### 2.6 如何做（技术挂点）
- **复用**：账号 / `MindSpace` / `Echo` / 生命之书；可见性字段挂 profile/space；`HostConfig`（broadcast/asyncOnly 等）作可见性开关雏形。
- **新增**：窗口页（H5 免登录、静态/SSR 渲染）、可见性颗粒度模型、献花机制（发起方额度/购买/种类/"记得"人数计数/私密羁绊，**不入宠物温度**）、分享物料生成、轻量内容审核队列。

### 2.7 匿名游客账号与转化漏斗（关键修正）

**"免登录" = 匿名游客账号，不是无账号。** 访客一进窗口页就是"用户"，只是没绑定，内部走与正常用户同一套逻辑——否则匿名用户不进闭环、无法培育与转化。

- **进入即建号**：访客点链接 → 自动分配**匿名游客账号**（设备/会话标识），无需注册。
- **游客可完整体验（照跑全量逻辑）**：浏览广场、进详情、**献花**（社交认可，记入"记得"人数与私密羁绊，**不影响宠物温度**）、甚至**开始给自己的它建档**（游客态）、产生偏好。
- **资产持久化在匿名账号**：献的花、建了一半的档、浏览/偏好——全部挂在这个匿名账号上，不丢。
- **转化点引导绑定**：到"想永久留住它 / 长期养护 / 跨设备 / 接收推送"等关键时刻 → 引导绑定（手机/微信）→ **账号升级/合并，游客态资产无缝继承**。
- **技术映射（交后端把关）**：复用现有 `Account`（`status` 字段承载 匿名/已绑定 两态）+ 匿名会话令牌 + 绑定时资产合并；细节由后端定。
- **红线**：游客同享私密与温柔基调；不因"未绑定"就骚扰或降级体验。

### 2.8 能做到什么程度（本玩法分档）
| 档 | 内容 | 可行性 |
|---|---|---|
| L1 较快 | 私密/公开二档 + 窗口 H5 页 + 分享卡 + 建档 CTA + 献花计数 | 高，复用现有 |
| L2 中期 | 挚友/共同守护 + 颗粒度控制 + 献花机制(额度/购买/种类/私密羁绊) + 回访推送 | 中，需审核 |
| L3 远期 | 窗口聚合为公共"共忆流" + 跨宠相遇入口 | 衔接下一玩法 |

## 2.9 亲友列表 & 动态圈（「我的它」内 · 承载"社会链条"的轻关系层）

在「我的它」页主卡下方一行"亲友列表",把挚友/家人这条关系线做进日常动线。

- **位置与折叠**：主卡下方、明信片墙之上，一行横向头像；**点表头可切换隐藏/展示**整行（记忆状态）。
- **排序**：默认 **优先置顶 → 在线 → 离线**；用户可自设"优先展示"，置顶者带标记。
- **进入主页**：点头像 → 切到该亲友/家人的主页（其"我的它/窗口"视图）。
- **「不看」三档**：每个亲友可设 **7 天 / 3 个月 / 永久** 不看——期间不看其信息与动态，移入"不看的亲友"折叠组，可随时恢复。（尊重用户对信息流的掌控，符合"不骚扰"红线。）
- **reel 动态圈 = 动态通知窗口**：当某亲友有"**当前用户有权查看**"的新动态时，其头像显示**渐变光环**，暗示可点击查看；无新动态则普通头像。可见性遵循对方的可见性设置（§2.1/§2.7）。**它只负责露出更新，点进去用的是统一互动系统（§2.14），不自带一套独立互动。**
- **产品分寸**：亲友动态是"温柔的近况"，不是社交攀比流；不显互动数排行；"不看"是温柔静音而非拉黑。

## 2.10 共同守护（2:1 · 纯情感共担）—— 已定

**核心决策**：共同守护 = **情感共担**，不背"社会链条"使命；社会链条交给 §2.9 亲友层（单向关注+动态圈）。**别让一个功能背两个使命。**

- **形态**：默认 **1:1**；owner 可**可选、需双方确认**地邀请**至多 1 位**"共同守护者"（伴侣/家人）= **2:1**。不做开放式多人/群组共养。
- **权限骨架**（owner 为最终权威）：
  | 能力 | 共同守护者 | owner |
  |---|---|---|
  | 维护/**填充过往**（回忆、明信片、留念） | ✅ | ✅ |
  | 献暖意/参与日常守护 | ✅ | ✅ |
  | 查看（含私密，受隐私隔离约束） | ✅（除隔离项） | ✅ |
  | 改核心设定/基调锚 | ❌ | ✅ |
  | **道别/删除/抹杀/转让** | ❌ | ✅ 独占 |

- **四条保护**（堵住共养的坑）：
  1. **填充标来源**：每条回忆/明信片标记"谁填的"，owner 保留自己的"正典视角"。
  2. **温柔解绑**：守护者退出 ≠ 暴力删人/删记忆；共同记忆可选保留、退出体面（防关系破裂的二次伤害）。
  3. **人格一致性保护**：喂基调引擎时 **owner 信号为主锚、守护者为补充（非等权）**，防人格失真/"精分"。
  4. **隐私隔离**：owner 可保留"只属于自己和它"的私密角落，不被守护者看到。

- **反例意识**（为何克制在 2:1）：分手/离婚归属、情感权重不对等污染正典、双人输入致人格失真、身后归属纠纷、社交子系统庞杂化、私密珍贵感稀释——均通过"限 2:1 + 可选 + owner 终裁 + 四条保护"收敛。

## 2.11 「我的光谱」· solo 回溯空间（第三步·共鸣层）—— 已定方向

> 定案经过：曾设想"众包刻画他人/对人的社会评价"，因**供给死**（没人愿当评价者/坏人，参见 Peeple 反例）+ **自我营销悖论**（主体自发起=精修人设）+ **人人网化风险** 三重矛盾而**推翻**。现收敛为下面这版：一个 **solo 接收者模型**，并与主线合流。

### 定位：solo 接收者，不是社交网络
- **不是人人网**（对称社交、互相加好友、逼人表演）；是**非对称的接收者模型**：**你在自己的空间里回溯，外界的声音（echo）偶尔闯入、引起共鸣，但你是接收方——可听、可滤、主控权在你。**
- 面向**不想 / 不适合主流社交、更愿意回溯与追忆的人**——给他们一个退避所，而非又一个逼人竞技的广场。
- **暖色为主**：记忆里痛苦远少于快乐，人多在铭记美好；主色永远温暖，暗只是让它**不假、不精修**的那层阴影。

### 与主线合流（回应"主线要清晰"）
**光谱不是第二个产品，它就是主线情感空间的"情绪纹理"。** 往宠/往人的那个人，本就是"在自己的空间里回溯、接收被牵挂的 ta 与过往的回声、筛选"的**同一个接收者**。名字都对上了：**echo = 你接收回声**。
- 主干：回声·往宠/往人（私密陪伴疗愈）。
- 「我的光谱」= 这个空间累积出的、你自己的**明暗情绪星云**。

### 暗面 = 你自己的内在阴影（技术涌现，非他评）—— 关键定案
**暗不靠任何人来写**（这解决供给死/不用谁当坏人），而是**从真实纹理里由技术悄悄涌现**，且**只做"你自己的内在阴影"（自我镜像），绝不做"外界对你的隐藏负面"**（后者=升级版 Peeple，制造"人人都在暗暗评判我"的偏执，是生死线红线）。

**技术管线（几乎全复用现有架子）：**
1. **采信号**：你收到的回声/留言/互动 + 你自己回溯的文字（记忆本身也有潜台词）。
2. **析潜台词**：`ILlmClient` 做**隐含情绪抽取**——不是好/坏二元，而是识别犹豫、疏离、矛盾、怅然、遗憾等暗流，输出小情绪向量（非判决）。
3. **悄悄归集**：`IVectorStore`(pgvector) 累积向量；**暗面只在跨过密度阈值、多信号彼此印证时才浮现**——单个零星信号绝不成暗（实现"悄悄形成"：水面下累积，攒够才显形）。
4. **氛围化呈现**：暗以星云**冷色区**存在，**不可归因**到任何一条/任何人、**不指控**——是质感/情绪，不是"谁说了什么"。

### 心理安全底座（最高优先级：绝不把用户搞崩）
- **外界是"可接收"，不是"强加"**：外界回声默认**经聚合/柔化、用户可滤**才进入，**任何单条他人言语永不以原文尖锐地直击用户**。
- **暗只源于自我涌现，不由他人一句话左右**：外界的只言片语**不能单独形成暗、不能直接拉低用户**；暗必须跨阈值、多信号、且始终框定为"你自己的内在阴影"。
- **永远有光的地板**：任何时刻光面在场，暗不淹没主体（60% 地板类比）。
- **可退可关**：用户随时可关暗面、屏蔽外界、退回**仅本人可见的自省模式**。产品宁可少一点"真实冲击"，也不制造崩溃。

### 保护与呈现
- **主体主权**：本人 opt-in；控公开档位（私密/关系内/公开）、**是否看暗 / 何时看清**、随时收回退出。
- **非对称可见**：主体看到的是更柔、聚合、成长框架版；"看清"某片冷色区是主体自主的仪式。
- **光不被暗吞（结构地板）**：光暗并置，永远同时陈列光面，避免全暗淹没（类比宠物 60% 温度地板）。
- **整合 ≠ 收集**：主流社媒收集赞；我们的核心动词是**整合**——接纳/回应一片暗，它不消失而融入星云成为立体的一部分（=你说的"历练/协调自己的复杂性"）。**这是与主流社媒的机制分水岭。**
- **视觉**：呼吸的极光星云，非雷达图/评分卡（复用 §3.14）。

### 「别人对你」的温暖部分 → 走仪式化留言册，不走评价
人类只在**仪式化、限定场合、被允许温暖、互惠**时才会为他人写印象（同学录/毕业赠言/生日墙/赠别/悼词）。所以"别人对你"只做**温暖的仪式化留言册**（在生日/纪念日等时机邀亲友写一笔温暖印象或共同瞬间），**有供给、不伤人、不营销**，且直接反哺 §0.6"记得/共同锚定/桥"。

### 落地路径（风险从零逐级放开）
- **v-α 自我光谱（私域）**：自己的回溯内容 → 涌现自己的明暗星云。**零社交暴露风险**，先验证"呼吸星云"视觉 + "整合暗面"情感价值 + 潜台词抽取管线。
- **v-β 接收外界回声**：一扇窗访客的暖意/留言飘入，主体可听可滤；温暖仪式化留言册。
- **v-γ 去标识群像（A）**：羁绊/经历原型星座（恩师/外婆/深夜的灯）→ 共鸣与传播（沿羁绊轴，禁群体身份轴）。

### 红线
- **禁**：对人的社会评价系统、他人自愿/被迫的负面评分、"外界对你的隐藏负面"、具名可归因负评、定向刷暗、无同意曝光、造神/膜拜排行、功德敛财。
- 暗面**仅限自我内在阴影**、仅氛围化、仅跨阈值涌现、绝不可归因。
- 群像仅沿**羁绊/经历轴**聚合，**禁沿群体身份轴**（种族/信仰/性向/地域/职业）。

## 2.12 「体验复利」· 共鸣分享与商业化 —— 已定方向

把"不断构筑的回忆"体面地展现给共鸣者，作为**战略级护城河**（而非"卖票看回忆"的收费站）。

### 复利飞轮（复的什么利）
回忆一旦建成，分享**不消耗、反增值**：
1. 用户为爱投入 → 建成高情感浓度的**共鸣资产**；
2. （经同意）分享 → 打动共鸣者；
3. 三条回流：**被打动→自建**（获客复利，被感动而来，非投放）／**暖意送回→主人"被更多人记得"**（情感复利→留存，接 §0.6 桥）／**近零边际成本积累最深情 UGC**（内容复利）；
4. 更多建造者 → 更丰富的共鸣馆 → 吸引更多 → 循环。
- **护城河**：一座**为爱而非为流量**建成的深情内容语料库，clout 驱动的竞品结构性复制不了。

### 定性 reframe：观察者 = 共鸣者，不是看客
**观察者不是来围观别人的伤心，是来疗愈自己。** 他因自己获得慰藉而付费，不是买一张别人痛苦的门票。这是"体面"的地基。
- **体面靠去具象/普世化**：卖"感觉的形状"（"一个每晚在窗边等一个不会回来的身影的人"），不卖名字/照片/日记原文。深度靠普世，不靠暴露。
- **观察者来寻（pull），不被推送（push）**：一个准备好去感受时才走进的房间，不是伏击情绪的信息流。

### 变现（以护城河为主，变现是副产品）
优先级：**① 共鸣馆做免费漏斗**（被打动→自建，最强获客）＞ ② 观察者侧订阅（为"自己的沉静共鸣/陪伴空间"付费）＞ ③ 主人侧 premium + 克制致意经济。
- **不给"观看/共鸣"装收费站**；变现顺护城河自然长出。

### 建造者动机铁律（护城河的命）
> **建造者的动机永远是情感；钱与流量从别处来，绝不排行、绝不给建造者发钱或发赞。**
一旦"为爱建"变"为流量建"，护城河从根上烂掉（=grief 版 Instagram）。

### 非金钱回馈：「留一束光」· 多维体验（softened，非攀比）
纯零反馈太冷；给回馈，但**只回向"关系与意义"，绝不回向"名次与人气"**，且**质性不量化**。
- **观察者侧**：不是点赞，而是一个**多瓣、可平衡的表达控件**——把自己的**主观体验**分布上去，调和成**一束颜色独一无二的光**留在空间里（同献花/星云视觉语言）。
- **维度=体验，不是评判**：问"**你被触动了什么**"，绝不问"**他做得怎么样**"。维度越多越精准 → 光色越细腻有别。

  | 维度（观察者感受） | 光色 | 质感 |
  |---|---|---|
  | 被触动 | 暖金 | 微微跃动的火光 |
  | 想起了自己的谁（牵念） | 柔粉 | 缓缓晕开的粉 |
  | 被治愈·平静 | 湖水绿 | 稳定呼吸的绿光 |
  | 被陪伴·不孤单 | 蜜色 | 环抱状暖晕 |
  | 温暖·被融化 | 深琥珀 | 浓稠暖芒 |
  | 敬意·被这份爱打动 | 金辉带星点 | 庄重金光 |
  | 怜惜·心疼 | 暮紫偏暖 | 轻柔紫晕（克制） |
  | 淡淡怅然（真实的一点忧） | 雾蓝偏暖 | 极淡、边缘柔化 |
  | 希望·被鼓励 | 晨桃色 | 渐亮暖橘 |

- **动态维度**：可增维，但每维过筛——**体验非评判、安全非攀比**。
- **行为推断兜底**：不想拨控件的沉默观察者，用停留时长/浏览流线也留下一束柔光。

### 防火墙铁律（保护建造者、守心理安全）
- 原始多维输入 + 行为推断**只留在内部与观察者侧**；
- 建造者**永远只收到：模糊、正向、非唯一、不可比较**的暖意（"有人留下一束偏向『被陪伴』的蜜色暖光"＋偶尔一句模糊正向），**绝不出现评分卡/名次/批评**；
- 偏冷维度（怅然）译到建造者侧也温柔（"有人在这里静静停留了很久"），守 §2.11 心理安全底座。

### 红线
- 不卖 grief 奇观、无"最催泪/最多人看"排行、不拿别人的痛做流量；
- 不把"被记得"做成 pay-to-play、不制造"不付费就没人记得 ta"的愧疚；
- 共享必须：显式同意 + 可匿名 + 可随时撤回；
- 观察者永远框定为共鸣者，不给猎奇/评判入口。

## 2.13 侧写引擎 · 双向 & 「向前的光谱」 —— 已定方向

把整条产品线合体的**脊柱**：同一台侧写引擎，跑两个时间方向。

### 统一洞察：一台引擎，两个时间方向
- **被牵挂的 ta（宠 / 人）**：引擎向**过去/侧旁**跑 → 勾勒 ta**继续存在**的样子（情感陪伴主线，§往宠核心 loop）。
- **用户自己**：引擎向**未来**跑 → 勾勒你**正在成为**的样子（成长向前）＝**「向前的光谱 / 明日侧写」**。

> 🔴 **术语更名（2026-08-25，依 `COPY-GUIDE.md` R1/§2.5 ②）**：本文原用「**往者**」指代引擎向后跑的那一侧，**统一改为「被牵挂的 ta」**。原词直接断言对象已逝，会把异地、失联、久病分离、走散这类同样需要这台引擎的对象排除在定义之外——而引擎向后跑取的是**已发生的素材**，与对象在世与否无关。对侧的「生者」一并改为「用户自己」：留着它，"往者"的死亡含义就靠这个对照又渗回来了。
> **被牵挂的 ta 的状态由 context 显式携带**（`unknown` / `deceased` / `living`），不由引擎推断；`living` 时不生成 ta 的口吻（`COPY-GUIDE.md §2.7`）。
- **同一套取材、同一套侧写、同一套共鸣**，只是时间指针方向不同。串起 §0.6 桥、§2.11 光谱、§2.12 复利，与"往宠→往人→大环境"路线图。

### 「向前的光谱 / 明日侧写」定义
基于用户**真实的过去**，轻轻勾出一个"**可以成为**"的未来自我；用户自己认同/塑形，别人只能接收共鸣。是 `我的光谱(§2.11)`（照见现在的你）的**向前姊妹**。

### 三条守则（生死线）
1. **有根，不捏造**：必须取材真实过往/活动 + **可能性框架**（"你**可以**成为……"，非"你**就是**……"）+ **用户认同塑形**（挑哪条未来像你，反向喂养）。是**邀请**，不是**预言**；有根=鼓舞，凭空=自欺/自我营销（已杀）。
2. **活跃度只正向、绝不惩罚**：越参与越**丰盈**；停下来只是**静止，不凋零、不羞辱**。**生长可挂钩活跃度，存亡不挂钩**（守"不焦虑/不惩罚/60% 地板"红线；反例：不登录未来自我就崩塌＝情感勒索，禁）。
3. **自著 + 他人只共鸣**：你自著、你认同，别人只能"接收/留一束光"，**无人能评判你**（守 §2.11/§2.12 线）。

### 顺解"客观 vs 独立隔离"的张力
**真实取材 = 客观**；**你自著 + 他人只共鸣不评判 = 独立隔离**。一体两面，不矛盾。

### 路线图接法
- **往人 step2**：同一引擎的另一个出口（往宠画像技法扩到"人"的角度）；人相关内容公开门槛更高（见 §3）。
- **大环境 step3**：向前侧写 + 群体共鸣是通往"向量映射/群体回忆"大环境的building block；先建砖，不过度承诺。

### 红线
- 未来投射**禁无根捏造、禁包装成事实/预言**；
- **禁**以"停用即衰减/崩塌"制造焦虑；
- 他人对用户本人的向前侧写**只可接收共鸣，禁评判/评分**；
- 往人方向沿用 §2.11/§2.12 全部保护与红线。

### 首页/共鸣厅 = 被接住率/健康度为目标的个性化(落地 2026-07-28 · CM1 修订 2026-08-04)
> **CM1 修订(运营 Moat-GTM)**:推荐**主目标 = 被接住率 / 续发率 / 健康度**(低撤回、低举报),**不以停留/公开互动做正向最大化**。停留信号降为**弱信号 + 负向护栏**(用于个性化匹配气质、识别"疑似被围观/消费悲伤"并降权),不再是排序的优化目标。
- **停留信号(engagement signals)**:完播、停留时长、复播、回访频次——**仅作私域个性化输入与护栏,不作最大化目标**。
- **用途一 · 广场共鸣排序**:以**被接住/健康度**为优化目标,叠加共鸣相似度个性化(气质相近);需 embeddings/向量(功能 J)。
- **用途二 · "今日一处"**:一个温柔小窗,把**你反复回味/停留很久的**再托出来("你似乎很在意这处,要不要再看看/记得它")——是个性化回访钩子,不是编辑硬推。
- **连续浏览(定案 2026-07-28)**:进入某窗口后**支持上下滑到下一条**(沉浸式连续浏览,顺共鸣个性化排序取下一个),**无限下翻、不加强制间隔**(流畅优先);但**保持安静基调**——无自动播放、无挑逗式预览,过渡安静。停留/完播/复播即时回流个性化(用途一/二)。
- **红线(必守)**:停留信号**仅作私域个性化输入**(同"看过数"内部性),**绝不聚合成公开的"最多人看/完播榜/停留榜"**(守 §2.14 无攀比榜、§0.7 记得不排名)。

### 空态 & 游客首屏(落地 2026-07-28)
- **游客首屏 = 直接进广场浏览**(低门槛,先被内容打动再转化);浏览中/被打动处自然露出建档 CTA("为你的它也建一扇窗")。
- **空态**(无宠物/亲友/记录/消息):**温柔文案 + 单一引导 CTA**,不留冷白空白(对齐 `ACCEPTANCE §3`);如"这里还很安静,要不要为它建一扇窗"。
- 新手核心转化路径:广场浏览 → 共情 → 建档("念念不忘,必有回响")→ 初见回声到达(§3.2)。

### 统一互动系统:一套互动,多处入口(不做两套)
**互动模型只有一套**(下方阶梯);reels、消息集散地、一扇窗、亲友主页都只是**露出更新 + 把你导进同一套互动**的**入口/界面**,各入口**不得自带一套独立互动**。
- **reels = 动态通知窗口**:只负责"有新动态"的提示与预览,点进去用的是同一套 L1–L4 互动。
- 保证:同一个"留一束光/记得/共同锚定/回信"在任何入口里语义、数据、规则完全一致。

### 互动阶梯(统一模型,由浅入深)—— 开放至 L1–L4
| 层 | 互动 | 深在哪 |
|---|---|---|
| **L1 轻回应** | 留一束光 / 记得 / 私密耳语 | 已有 |
| **L2 共鸣表达** | "我也是"共振(=我也想起了我的谁) / 续写一句 | 反应→共鸣 |
| **L3 参与共创** | 补一个视角(丰富 ta 生命之书,经主人同意) / 同款回忆私密交换 | 看→一起建 |
| **L4 情感往来** | 回信 / 递一样东西(花·叶·歌进 ta 空间) / 共忆仪式(约时刻一起点灯) | 异步→往来/在场 |
| **L5 关系沉淀**(建向目标) | **共同锚定 →「我们之间」共同记忆** | 互动累积成关系资产 |

### 两个优先深挖的深水区
1. **共同锚定 →「我们之间」的共同记忆**(§0.6 桥落地):两个都记得同一瞬间的人一起确认它 → 升级为"双人共同记得的",沉淀进私密的「我们之间」空间。**主流社媒有"我发的",没有"我们共同记得的"——独一份、越攒越厚的关系资产。**
2. **在场/陪伴作为互动**:"陪 ta 坐一会儿" / 两人"一起点一盏灯"(同步或异步)。**无数字,只有"你来过、你陪过"——最温柔、最不社媒的互动。**

### 守线(开放但不塌)
永不碰:公开点赞数、盖楼比拼、"谁互动最多"的榜、把陪伴变成打卡义务。**互动可多可深,但永远是暖意与共鸣,不是竞技与表演。**

## 2.15 明信片墙 · 解锁规则 —— 已定（§0.7 #2）

明信片墙位于「我的它」主卡与亲友列表之下（§2.9），是宠物陪伴的**收集式回忆载体**。

### 解锁机制（双轨）
- **基础轨（人人平权）**：明信片随**陪伴里程碑**自然解锁——温度阶段、相伴天数（百日/周年）、关键回忆归档、共同锚定等。**每位用户都有基础墙，差异只在"收集进度"，不在"有没有资格"。**
- **付费轨（只加速/只样式）**：可付费**加速解锁进度**或购买**限定款式**（节日/纪念日限定的皮肤·边框·材质·动效）。

### 护栏（红线，写死）
- **绝不把"某段回忆内容本身"锁进付费墙**——一段回忆、一张明信片承载的"内容"永远靠陪伴解锁；付费只买"更快"和"更好看的壳"。
- 付费款式**不产生任何攀比/排名**，与献花、记得同守 §3 红线。
- 限定款下架后**已拥有者永久保留**，不做 FOMO 逼单。

### 落地
- 复用生命之书里程碑事件流触发解锁；款式作为素材皮肤挂 profile；付费走订阅/单购（§2.8 变现档）。

## 3. 全层红线
- **私密永远优先**：公开逐项显式勾选、可随时收回；1v1 私密陪伴始终是主轴。
- **不做攀比**：无排行等冷指标；社交货币是"被记得"，不是"赢赞"。⚠️ **2026-08-25 回改**：本条原写「无粉丝数/排行」，**「无粉丝数」部分已被推翻**——粉丝数公开且为精确数字，但**仅个体页可见**、不上信息流卡片、🔴 **不做任何按粉丝数排序的列表或榜单**（`D14` 不推翻）、🔴 **不进排序**（`X12`）。「不做攀比」的红线本身**不放松**：划线的地方从"有没有这个数字"改成"平台有没有拿它制造名次"。**依据**：制作人 2026-08-24 裁定，见 `SPEC-recommendation-ranking.md §15 RK14`/`RK36`、`§1.5`、`§9 红线三`。
- **防 grief 公开化伤害**：公开态基调仍温柔，重审核、禁恶评、留言可审。
- **接力/匹配禁物化**：一律"接续/永存/新缘分"叙事，绝不暗示"换一个就好"，绝不用逝者身份套新宠。
- **人（逝者）相关内容**（step2）公开门槛更高；本层**先只做宠物**。
