## 1. 本次试用与核心发现

### 1.1 使用的虚构样例

> 以下内容仅用于本地 mock 试用，不含真实用户或真实宠物资料。

| 字段 | 样例 |
|---|---|
| 名字 | 团子 |
| 种类 | 狗狗（mock 识别返回） |
| 性情 | 温柔、爱晒太阳、爱钻被窝 |
| 回忆 | “团子喜欢在午后的窗边打盹，也总会在下雨时钻进我的被窝。” |
| 试用路径 | 肖像上传 → 识别确认 → 命名 → 补充素材跳过 → 特征/故事输入 → 定妆候选 → 游客广场/窗口 → 记得/献花 |

### 1.2 试用结论

1. **输入端太像“AI 表单”，输出端才像情感产品。** 先上传、再识别、再从 60 多个特征中选择，会让用户以为自己在训练模型，而不是留下回忆。
2. **定妆是最重要的承诺点。** 用户已经交出图片和故事，期待的是“被准确地理解”；候选卡目前没有展示“为什么像它”，且演示 mock 出现“识别为狗、候选却为人物”的输入输出失真。即便只是 mock，也不能用于种子测试。
3. **互动已具备正确雏形，但语义需收紧。** “记得”清晰而不竞争；“献花”仍在“给主人”与“给它”之间摇摆。
4. **真正的社交价值不是浏览他人的失去，而是获得恰当的共鸣。** 广场可以是入口，但不应成为产品中心；公开不应是建档后的自然下一步。

## 2. Echo 与主流社交产品的本质差异

主流社交的基本模型是：创作内容 → 分发给更多人 → 通过互动和数据反馈扩大关系。TikTok 允许按每条内容选择公开、好友/关注者或仅自己可见，公开内容还可能被站外看到；Instagram 的转发同样依赖原作者公开账号和允许转发。它们的隐私控制解决的是“**谁能看到**”，但产品动力仍是分发和可见性。 [TikTok 可见性说明](https://support.tiktok.com/en/account-and-privacy/account-privacy-settings/video-visibility?lang=nl) [Instagram 转发说明](https://www.facebook.com/help/instagram/1013375002134043?locale=en_GB)

Echo 要解决的不是曝光，而是“**什么可以被留住、被谁以什么方式靠近**”。这意味着它应采用另一套体验语法：

| 维度 | 主流内容社交 | Echo 应采用的逻辑 |
|---|---|---|
| 内容起点 | 为表达/被看见而发布 | 为自己保存；分享是第二步、且必须有理由 |
| 默认可见性 | 因产品而异，但公开分发是核心路径 | 私密默认；每一类素材、每一个窗口、每一次导出独立授权 |
| 反馈 | 点赞、评论、转发、播放/阅读数 | 记得、留一句话、留一束花；不显示竞争数字 |
| 推荐 | 最大化停留与分发 | 最小化打扰；只在用户主动浏览时给“可能愿意靠近的窗口” |
| 关系 | 关注/粉丝为主 | 所有人、共护者、受邀亲友、匿名来访者分层 |
| AI | 生产更快、内容更多 | 帮用户整理记忆；不替代用户叙述，不伪装事实 |
| 增长 | 热点、创作者、规模 | 信任、保存价值、经同意的分享、口碑转介 |

微信/WeChat 的隐私政策也明确提及用户可以在 Moments 中公开分享文字和图片；这恰好提醒我们，Echo 的素材敏感度更高，不能简单沿用“朋友圈式公开/分组”就视为足够。 [腾讯隐私保护平台](https://privacy.tencent.com/mb/policy/tencent-privacypolicy)

### 运营判断

**不要把 Echo 做成低互动版小红书或温柔版抖音。**

如果广场变成主要日活入口，产品会不可避免地滑向：更好看的封面、更抓人的失去叙事、更多被记得。这与“不消费悲伤、不制造比较”的理念冲突。广场的任务应该是提供“我原来可以这样安放一段陪伴”的理解样本，而不是承载内容竞争。

## 3. 建议的核心模型：记忆库、窗口与回声三层分离

当前设计将建档、宠物档案、窗口页、回声与公共互动放在一条理解链里，用户容易误以为上传即公开。建议明确拆成三层对象：

```text
记忆库（绝对私密，原始照片/录音/文字）
   └── 它的档案（私密默认，用户整理后的长期记录）
         ├── 回声（基于已授权片段生成；可关闭、可改写、可删除）
         └── 一扇窗（显式创建的“分享副本”，可独立编辑、随时收回）
                ├── 受邀亲友
                ├── 仅持链接可看
                └── 审核后公开展示（P1 后）
```

关键不是文案，而是权限数据模型：

| 对象 | 默认 | 可选范围 | 必须具备的操作 |
|---|---|---|---|
| 原始素材 | 私密 | 不可直接公开 | 删除、下载、撤回 AI 使用授权 |
| 记忆片段 | 私密 | 仅自己 / 亲友 / 可进入窗口 | 编辑、隐藏、从回声来源中移除 |
| 回声 | 私密 | 仅自己（P0）；可选展示到窗口（P1） | 换一种说法、暂时不要、删除、查看来源范围 |
| 一扇窗 | 不自动创建 | 受邀 / 持链接 / 审核后公开 | 预览、字段级选择、到期、撤回、举报/下架 |

这会使“可见性三档”从一个设置项，升级为用户能理解的承诺：**我分享出去的是一扇整理过的窗，而不是把整个记忆库递出去。**

## 4. 便捷性与实用性：把“建档”改成渐进式留下

### 4.1 首次体验改造

现状：打开即肖像上传。  
建议：打开先给两条同等权重路径：

```text
先看看别人怎样记得  → 游客广场（只看审核样本）
为 ta 留一处          → 选择“从一句话开始”或“从一张照片开始”
```

“一句话开始”尤其重要。用户可以先写“它最爱晒太阳”，获得一个私密空白档案；照片、语音、更多素材均在后续补充。这既降低隐私门槛，也符合“回忆不是一次性填表”的事实。

### 4.2 输入组件收口

| 当前 | 问题 | 调整方案 |
|---|---|---|
| 首屏必须上传肖像 | 信任未建立就索取敏感素材 | 图片/一句话双入口，任何时候可跳过 |
| 60+ 性情标签平铺 | 认知负担高、像问卷 | 先给 6 个情景卡：`它最常做什么？`、`你最想记住什么？`；“更多特征”折叠 |
| “为它定妆”三选一 | 用户难判断三张为何不同、存在误导风险 | 每张标明差异（更像照片/更像记忆中的它/更安静）；必须有“都不像，先不选” |
| 回声直接生成 | 用户不知依据、易感到被替代 | 回声下方提供“这段来自：窗边打盹、下雨钻被窝”；展示来源类别，不暴露原文 |
| 可见性放在“我”页 | 分享决定被后置，用户难建立安全感 | 创建窗口时做字段级预览与权限选择 |

### 4.3 微交互规则

- **回声反馈三选一**：`想留下` / `换一种说法` / `暂时不要`，不出现点赞/踩。

## 5. 互动与分享：将“社交”定义为被授权的靠近

### 5.1 互动语义定稿建议

| 动作 | 对谁 | 用户看到的反馈 | Owner 看到的反馈 | 规则 |
|---|---|---|---|---|
| 记得它 | 对这段陪伴 | “你也在这片暖光里” | 暖光/头像（可选） | 开关式；不显示总人数 |
| 留一句话 | 对 owner 与窗口 | 仅在 owner 审核后可见 | 待确认的留言 | 默认不公开，避免情绪负担 |
| 留一束花 | 对这份想念/给主人 | “留下了一束心意” | 心意提醒 | 不产生温度、热度或兑现关系 |
| 邀请亲友 | 对窗口 | 生成私密邀请 | 可随时撤销 | 受邀者不能再分享，除非 owner 开启 |
| 分享窗口 | 对外 | 生成经过裁剪的链接卡 | 可设置有效期 | 默认不含原始图、精确互动数或可下载项 |

建议把“献花”对外统一叫 **“留一束心意”**。在内部和计费体系仍可保留 flower，但用户侧不要出现“我为它献过 X 朵花”这种对象混乱又易游戏化的表述。

### 5.2 分享不是按钮，是一个小流程

建议在分享前增加“窗口预览”页：

1. 选择一件想让别人看到的事（而不是默认整个档案）。
2. 勾选允许出现的字段：名字/照片/生命片段/留言/回声。
3. 选择范围：`只给亲友` / `持链接可看（7 天）` / `申请公开展示`。
4. 展示收回按钮与“对方不能下载/再分享”的说明。

这借鉴主流产品“每条内容独立设可见范围”的便利性，而不是复制其公开分发逻辑。TikTok 允许用户在发布时和发布后修改每一条内容的受众范围；Echo 应进一步做到“每一扇窗、每一类字段”都可撤回。 [TikTok 官方说明](https://support.tiktok.com/en/account-and-privacy/account-privacy-settings/video-visibility?lang=nl)

## 6. P0 / P1 范围建议
