## 0. 策略与关键判断

- **第一步用 H5**：无商店审核、改版即上线、裂变链接天然（一扇窗分享），最快拿到真实闭环反馈。
- **长期主战场是 App**：核心留存钩子「回声周期推送」（前 3/5/7 天定时来信）H5 撑不起，必须靠原生 push。
- **资质并行**：ICP 备案 + 软著 + AI 备案周期 1–2 月，**从第一天与开发并行启动**，否则 App 阶段白等。
- **两个卡脖子风险**（§4 专项）：**版号**（养成/数值/付费道具可能被判游戏）+ **生成式 AI 备案**（宠物来信是 AI 生成）。

## 4. 两个战略风险 · 专项

### 4.1 版号规避（产品定性仗，从第一天打）
- **风险**：温度养成 + 数值 + 付费道具（献花/明信片款）具备"游戏特征"，可能被判游戏→需版号（周期长、难拿）。
- **关键认知**：**换变现方式（广告/打赏）本身绕不过版号**——决定版号的是"是否被判定为网络游戏"，变现只是判定信号之一。真正的绕法 = **整体定性为非游戏（情感陪伴/数字纪念/内容社区/工具），玩法+变现+话术三者一致弱化游戏属性**。
- **规避策略**：
  - 定位统一为 **「情感陪伴 / 数字纪念 / 记录工具 / 社交」**，对外话术、商店类目、软著名称一致；
  - **弱化玩法/竞技词**（不叫"玩家/关卡/PK/战力"）；献花/明信片包装成 **「纪念心意 / 纪念收藏」** 而非"游戏道具/虚拟货币"（用词护栏见 §8）；
  - 温度呈现为"陪伴暖意"而非"数值养成"；
  - **变现走应用/内容/工具类标准模式（订阅+装饰增值），不碰虚拟货币道具**（§8 白名单）；
  - **P2 前请法务出定性结论**，别到提审才发现要版号。

### 4.2 生成式 AI 备案（与 AI 中台直接挂钩）
- **风险**：宠物近况/来信是 AI 生成内容，国内强监管，需算法备案（视规模含大模型备案）。
- **要理清**：
  - **阶段一用外部 API**：备案主体、生成内容责任、供应商已备案能力如何借用/如何自担；
  - **将来自托管/自研模型**（`TECH-AI-PLATFORM.md` 阶段二/三）：需自行备案，提前规划；
  - 生成内容需可追溯、可标识（AI 生成标识）、有安全过滤（基调+安全层已覆盖红线）。
- **动作**：P0 即让法务/合规介入，与技术选型（build-vs-buy）联动决策。

## 8. 变现护栏（定案 · 既规避版号又守基调）

**原则**：只用应用/内容/工具类标准变现；不碰游戏信号（虚拟货币道具），不碰消费悲伤（用哀伤数据做定向推广）。

### 8.1 变现白名单（可用）
| 模式 | 定位 | 备注 |
|---|---|---|
| **订阅会员制**（月/年） | 主力 | 可持续扩展权益；注意苹果 IAP/自动续费合规 |
| **装饰/服务增值**（明信片款式·边框·材质·一次性解锁） | 辅助 | 框成"装饰/服务"，非"游戏道具" |
| **数字纪念服务**（AI 生成纪念内容、定制形象、导出纪念册） | 辅助 | 卖服务/内容，纯工具属性 |
| **纪念衍生电商**（把回忆做成实体纪念册/相框/摆件） | 加分·后置 | **用记忆信息为用户创造纪念物（用户受益）**；走第三方支付；干净无版号 |
| **主动逛的「纪念商店」** | 加分·后置 | 用户**主动进入**选购纪念主题商品，**非定向弹推** |

### 8.2 变现黑名单（不碰）
| 模式 | 原因 |
|---|---|
| **虚拟货币/礼物道具**（买币→消耗道具） | 强游戏信号 → 触发版号 + 需资质 |
| **基于记忆/哀伤数据的定向商品推广** | **消费悲伤（grief-as-commerce）= 命门红线**；PIPL 敏感信息营销高风险；舆情灾难。**只允许"用户受益"版（§8.1 衍生/主动商店），禁止定向推送** |
| **情感场景插广告**（信息流/开屏等） | 毁基调 + 伦理/舆情风险 |
| **打赏/tipping**（第一版） | 可能需文网证/直播资质 + 未成年退款 + 与"留一束光=非金钱回馈"（PRD §2.12）价值观冲突 |

### 8.3 献花 · 去游戏化用词护栏（reframe 定案）
- 保留"每日 5 朵免费 + 可购买"，但**形态与用词去游戏化**：
  - **禁用词**：金币 / 虚拟货币 / 道具 / 充值 / 背包 / 商城（游戏味）；
  - **推荐词**：心意 / 致意 / 一束花 / 补充 / 心意商店；
  - 形态上**不做"买币→消耗代币"的两段式观感**，直接"补充花的份额"；
  - 与温度、排名保持解耦（PRD §0.7 #3/#5 不变）。
- 同步落 `COPY-GUIDE.md` 禁用/推荐词。
- **礼物模型借鉴口径（定案 2026-07-27）**：献花可**借鉴抖音/小红书"虚拟礼物赠送"的 UX**（分层礼物、赠送即表达、节日限定、整束=心意浓度），但**刻意砍掉打赏经济的两截：不可提现、不给主人分成**——因此属常规内容/增值付费（§8.1），非直播打赏。**"主人收花变现/分成"= 打赏范畴，触发文网证/直播资质+未成年退款+价值观冲突（§8.2），第一版不碰、后期单独评估。**

### 8.4 「暖意」非货币定性（定案 2026-07-27）
- **暖意不是虚拟货币**，是**类抖音"热度"的活跃指标**：玩家活跃行为（点赞/到访/互动）对"它/温度"的影响度，**永不可被直接购买**。
- 因此**不构成"买币→消耗道具"的游戏虚拟币信号**（§8.2 黑名单不适用于暖意）；订阅只提升暖意累积上限/速率与自动维系温度（买便利/呈现，非按份卖暖意）。
- 界面用词避免"货币/金币/余额"，用"暖意/热度/爱心 ❤"。详见 `PRD-echo-pet.md §3.11②/§7.2`。
