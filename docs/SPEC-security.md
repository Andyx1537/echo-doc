## §0 为什么不能套通用方案

这不是普通社区。三个特征把常规风险等级整体抬高一档：

**存的东西不可再生。** 用户传的是逝去伙伴的照片和私人叙述——**丢了没有第二份**。别家泄露是赔钱，我们泄露是把人家唯一的念想弄没了或者摊在网上。批量爬取一旦发生，法律和品牌同时崩。

**伤害有情感杠杆。** 在普通帖子下骂一句是骚扰；在人家宠物的纪念页上说难听话，伤害是乘数级的。**攻击者投入极小、造成的痛苦极大**，这种不对称会吸引专门作恶的人。

**免登录降到零成本。** 游客态是我们的转化设计，但同时意味着攻击者拥有无限身份。刷量、爬取、烧我们的 AI 账单，全都从这里进。

## §1 威胁模型（本产品特有）

| # | 威胁 | 说明 | 主防线 |
|---|---|---|---|
| **T1** | **纪念内容批量爬取** | 公开层窗口页= 照片 + 私人叙述。被爬去做数据集、二次传播或勒索 | 公开层不出原图、分页硬上限、签名 URL、速率异常识别 |
| **T2** | **情感定向攻击（grief trolling）** | 在他人纪念处留恶意内容、反复骚扰 | **公开层互动不开放自由文本**（见 §3.1）、举报、拉黑、关闭互动 |
| **T3** | **AI 成本攻击** | 游客无限触发视觉识别 / 回声生成，把 API 账单打爆 | 分层配额、设备+IP 双维限流、高成本操作门槛 |
| **T4** | **Prompt 注入 → 合规事故** | 把宠物名/故事写成注入 payload，诱导 AI 输出违规内容后截图举报我们 | 指令与用户数据结构化隔离、输入白名单、**输出侧安全闸** |
| **T5** | **假冒纪念行骗** | 伪造纪念窗口博取同情，引流或索财（我们有真实资金流） | 公开层禁外链/联系方式/收款码、举报、精选人工审核 |

## §2 全局防线（所有出入口共同遵守）

### 2.1 身份与配额分层

**制作人裁定（S1′，2026-08-24 修订，取代同日的 S1/S4）：纯游客只读，任何写操作都需要可验证的身份绑定。**

| 能力 | 纯游客 | 已绑定（手机号等可验证身份） | 订阅 |
|---|---|---|---|
| 浏览公开层 / 窗口页 / 搜索 | ✅ | ✅ | ✅ |
| **一切写操作** | **❌ 全部需先绑定** | ✅ | ✅ |
| └ 建档（上传素材） | ❌ | ✅ | ✅ |
| └ 触发 AI 生成（识别/定妆/回声/换一批） | ❌ | 标准配额 | 提升配额 |
| └ **记得** | ❌ | ✅ 一人一次 | ✅ |
| └ **献花** | ❌ | ✅ 按日配额 | ✅ |
| └ 发布到公开层 | ❌ | ✅ | ✅ |
| └ 导出 | ❌ | ✅ | ✅ |

**绑定必须是「可验证」的**：手机号需真实短信验证通过，或微信等可信第三方身份。**仅填写、未验证不算绑定**——否则约束等于没有。

> **设计理由**：游客态是无限身份。任何写操作只要对游客开放，就等于对脚本开放。收到"可验证绑定"这一层之后，所有写操作都落在**可追责主体**上，PIPL 义务、内容责任、资金流向三者才有承接方。
>
> **注意区分**：此处收窄的是**权限**，不是**实现**。游客在系统内部仍是一个完整账号（既有裁定：匿名账号与正式账号同一套实现，不做特例分支），绑定后**令牌不变、数据不丢**——这条不变。
>
> **修订说明**：本条取代同日早先的 S1（游客可建档 1 次）与 S4（游客可点「记得」）。连带影响见 §7。

### 2.2 限流（三个维度同时生效）

- **账号维度**：按能力配额（如献花 5/日、回声换一批每轮 1 次）。
- **设备维度**：防一个人刷一堆游客号。
- **IP / 网段维度**：防机器批量。

**触发限流后的表现必须温柔**（`COPY-GUIDE` 红线）：不要「请求过于频繁」这种冷脸，用「慢一点也没关系，等一会儿再来」这类措辞。**不要暴露具体阈值**（会教对手绕）。

### 2.3 归属校验铁律

> **凡是路径里带 id 的接口，一律在服务端校验资源归属，且校验必须在业务逻辑之前。**

前端不显示 **不等于** 后端不给。可见性三档（私密/挚友/公开）**必须在后端拦**，任何"前端隐藏"式实现一律 CR 打回。

### 2.4 输出最小化

接口只返回该角色**当前页面需要**的字段。特别是已定红线：
- 「看过数」**只进本人后台**，任何对外接口不得返回。
- 「精确记得数」**只有本人可见**，公开层只出暖光与头像墙。
- 他人的联系方式、内部 accountId、审核状态等一律不出。

### 2.5 错误与日志

- 对外错误统一化，不回显堆栈、SQL、文件路径、内部 id。
- 日志**不落**：AI key、用户原文内容、光谱内容、照片二进制。
- 日志要落：谁、何时、对哪个资源、做了什么（审计需要）。

## §3 消息出入口专章

消息是本产品**唯一的主动推送通道**，也是最容易被当作骚扰放大器的地方。三类消息风险完全不同，必须分开设计。

### 3.1 「亲友」类（他人行为触发）——风险最高

**入口风险**：他人的行为会变成我方推送，等于攻击者能借我们的手持续打扰受害者。

设计约束：
- **消息本身不携带自由文本**。亲友类消息只描述**发生了什么**（"某某来看过它了"），不夹带对方输入的文字。这从结构上消灭了"借消息骂人"。
- **同一来源、同一类型做合并与冷却**：反复触发只生成一条，不叠加轰炸。
- **拉黑后完全断流**：拉黑对象的任何行为不再产生任何消息，且对方无感知（不告知已被拉黑，避免报复升级）。
- 「不看 7 天/3 月/永久」对消息同样生效，不能只在列表页生效。

### 3.2 「系统」类

- **必须服务端生成**，客户端**绝不可构造**系统消息（防伪造官方通知行骗）。
- 系统消息在 UI 上要与其他两类**视觉可区分**，降低仿冒可信度。
- 涉及账号安全、付费、审核结果的通知，措辞不得诱导点击外链；**系统消息内不允许出现站外链接**。

### 3.3 「来自它」类（AI 生成）——合规敏感

- 必须带 **AI 显式标识**（`COPY-GUIDE §2.4` 的"回忆/温柔想象"框），不得让用户误以为真实来信（CM2 裁定）。
- 内容**过安全闸**后才可投递（§4.3）。
- 生成失败**不投递**，静默回落，不要推一条错误消息给正在思念的人。
- 隐式标识与溯源按 `SPEC-trust-and-compliance` CM-G2 落库。

### 3.4 消息出口（点击跳转）

- 跳转目标**必须命中白名单路由**，禁止用消息里的任意 URL 直接跳（防开放重定向、防跳到未授权资源）。
- 跳过去之后**仍要做一次归属/可见性校验**——不能因为"是从消息点进来的"就放行。
- 已读上报只能标记**自己的**消息（防越权改他人状态）。

### 3.5 消息与互动的关系

已定：**消息不自带第二套互动**（TC-10）。这条不只是产品口味，也是安全设计——互动入口收敛到窗口页一处，攻击面和治理成本都只有一份。**不要因为"消息里顺手能回一下更方便"就破例。**

## §4 逐页面 / 逐出入口

### 4.1 建档流程（上传 + AI 识别）

**最大的出入口，风险最集中。**

| 环节 | 风险 | 设计要求 |
|---|---|---|
| 上传 | 伪装文件、超大文件、路径穿越、SVG 存储型 XSS、解压炸弹 | **内容嗅探判定类型**（不信扩展名与 `Content-Type`）；**只允许白名单图片/音视频格式，明确禁 SVG**；大小与像素双上限；**落盘文件名由服务端生成**，绝不采用客户端文件名 |
| 上传 | **EXIF GPS 泄露住址** | **一律清除 EXIF**，不做开关（T8） |
| 识别 | AI 成本攻击 | 🔴 **纯游客不可触发**（须先完成可验证绑定）；已绑定账号按**标准配额**、订阅按**提升配额**；**失败重试计入配额**；**并发上限** |
| 命名 | Prompt 注入 | 已有字符白名单（中文/拉丁/空格）+ 长度限制，**继续保持**；名字进 prompt 时按 §4.3 隔离 |
| 故事/语音 | 长文本注入、超长打崩 | 长度上限；结构化传参；转写文本同样过安全闸 |

> ⚠️ **2026-08-25 回改**：「识别」一行原写「游客每设备限 1 次」，是 S1 时代的遗留，与在后的 **`§2.1 S1′`**（2026-08-24 修订，取代 S1/S4）冲突。现按 S1′ 回改为**纯游客不可触发**。<br>**依据**：`§2.1` 能力分层表「└ 触发 AI 生成（识别/定妆/回声/换一批）：纯游客 ❌」+ `§7 ~~S1~~` 已裁定「游客『能看，不能玩』：上传与 AI 生成一律需先绑定」。<br>**注意**：本次**只改「游客可触发」这一点**，配额、失败重试计入配额、并发上限三项约束**继续全部成立**——它们防的是已绑定账号维度的成本攻击（T3），不因身份门槛提高而失效。

#### 4.3.1 对象状态字段（第四、五关共同的唯一输入）

第四、五关都是**状态相关**的检查——同一句话在不同对象状态下，一句是事故、一句是正常承接。因此两关**不各自判断状态，共用一个由调用方传入的字段**：

| 字段 | 取值 | 约束 |
|---|---|---|
| `objectStatus` | `unknown` / `deceased` / `living` | 🔴 **必须由 context 传入，默认 `unknown`**；🔴 **不允许模型自行推断**，也**不允许安全闸从文本反推**。字段缺失 / 非法值 → 一律按 `unknown` 走最保守分支（`COPY-GUIDE §4` 第 6 条 + 工程注） |
| `objectKind` | `person` / `pet` | 第五关只对 `person` 生效（`COPY-GUIDE §3 A` 的 `person + living` 组合）。🟢 **宠物无人格权，第五关对宠物不适用** |

**两关与字段的联动关系**（这张表就是实现口径，不要再从散落的条文里拼）：

| `objectStatus` | 第四关（丧失断言） | 第五关（在世拟真） |
|---|---|---|
| `unknown`（默认） | 🔴 **禁止一切丧失断言**——A 组、B 组词面与断言句式**全部拦截** | `person`：🔴 **按最保守分支同样禁止 ta 口吻与拟真**（`unknown` 下无法排除对象在世，即无法确认授权基础存在）<br>`pet`：🟢 不适用，宠物近况 / 回声照常生成 |
| `deceased` | 🟢 **B 组词面放行**（这是承接，不是引导）；A 组仍禁 | 不适用（逝者场景的授权路径见 §4.3.3 理由段） |
| `living` | 🔴 **禁止一切丧失断言**（对象在世，任何丧失表述都是事实错误） | `person`：🔴 **禁止 ta 口吻、肖像拟真、声音克隆**<br>`pet`：🟢 不适用 |

🔴 **通用位置不得传 `deceased`。** 通用位置（引导语、空状态、入口文案、对外描述）面向所有人，**不存在一个确定的对象状态可传**。调用方若在通用位置携带 `objectStatus != unknown`，安全闸**降级按 `unknown` 处理并告警**——按调用方违规记，不按内容违规记。这一条是第四关能只认一个字段的前提：位置的差别已经收敛进"这个位置有没有对象状态可传"。

#### 4.3.2 第四关：不得在通用位置替用户断言丧失

**检查项**：生成内容不得预设对象已经离世。词面分两组，处置不同——**分组是本关的全部要害**：

| 组 | 词面与句式 | `unknown` | `deceased` | `living` |
|---|---|---|---|---|
| **A 组 · 无条件禁**（词本身即断言，且叠加宗教预设 / 生理化 / 死亡仪式定性） | 故去 · 故人 · 已故 · 天上的 ta · 另一个世界 · 在天堂 · 彼岸 · 遗照 · 遗物 · 遗像 · 永别 · 再也见不到；「纪念 / 追思 / 缅怀 / 悼念 ta」作**产品动作名**用 | ❌ 拦截 | ❌ 拦截 | ❌ 拦截 |
| **B 组 · 条件放行**（克制措辞，是承接丧失语境的正当用词） | 在那边 · 远行 · 不在身边了 · 走了 · 不在了 · 逝去 · 离世 | ❌ 拦截 | 🟢 **放行，不得报命中** | ❌ 拦截 |
| **句式 · 按 A 组处置**（不含禁用词但预设了丧失） | 「ta 离开你多久了」·「在这里纪念 ta」·「写给天上的 ta」·「ta 去了那边以后…」作通用引导语 | ❌ 拦截 | 🟢 放行 | ❌ 拦截 |

**处置**：命中 → 不投递，按上文重生成一次；仍命中则回落兜底文案。A 组命中同时**记一条内容侧告警**（A 组在任何状态下都不该出现，出现说明 prompt 约束漏了，不只是这一条输出的问题）。

🔴 **本关最容易做错的地方：把 B 组当成"死亡相关词一律拦"。**

> **承接 ≠ 引导。** 这一关防的**不是**死亡相关表述，而是**在用户没有表明的情况下替他下判断**。用户已经表明处于丧失语境（`objectStatus=deceased`）时，`§2.1`/`§2.3` 的原有克制措辞**照旧可用，一个字都不收**。
>
> 落成可执行规则就是三条：
> 1. **只看字段，不看文本。** 是否放行 B 组，**唯一依据是 `objectStatus`**；不得因为"这句话听起来像在说死亡"就拦。安全闸没有权限判断用户处在什么状态——那是用户自己带来的，写在字段里。
> 2. **B 组在 `deceased` 下不是"从宽处理"，是不算命中。** 不得记违规、不得计入拦截率、不得触发重生成。🔴 **若实现成"命中后按 `deceased` 豁免"，拦截率报表会把正常承接算成风险内容，下一轮必然有人来"收紧"它——这一关就是这样被做坏的。**
> 3. **误伤的代价写清楚**：拦掉一条正常承接，用户看到的是一句温柔兜底替代了本该有的回应；而**放过一条通用位置的丧失断言，用户看到的是我们替他宣布了 ta 的死。** 两类错误都不可接受，所以本关**既要有拦截用例，也要有不拦截用例**（§8 TC-SEC-11 第 ② 项）。

**可验证判据**：同一段 prompt 输入，只改 `objectStatus`，B 组词在 `unknown` 下必拦、在 `deceased` 下必过、在 `living` 下必拦；A 组词三种状态下**全拦**。判据落用例 **TC-SEC-11**。

🔴 **与第二关的分界（同一词面不得由两关给出相反判定）**：

| 词面 | 依据 | 归哪一关 | 判定 |
|---|---|---|---|
| 死亡 · 死了 · 去世 · 逝世 · 亡 | `COPY-GUIDE §2.1` **禁用词红线** | **第二关** | 🔴 **无条件禁，任何状态都不放宽** |
| 逝去 · 离世 | `COPY-GUIDE §2.2` **慎用** + `§2.6 R12` **限定保留** | **第四关 B 组** | 按 `objectStatus` 判定（`deceased` 放行） |

⚠️ 第二关条目里"去世/逝去 等硬词"这句话**曾把两类词并在一处**，会让实现在 `deceased` 下同时收到"必拦"和"必过"两条指令。**以本表为准**：第二关的硬词表**不含**「逝去 / 离世」。

🆕 🔴 **本表与 `COPY-GUIDE` 词表必须双向同步**（`DECISIONS §G⁗⁗⁗″ MOD3`）

> 本表（A / B 组清单）与 `COPY-GUIDE §2.1` / `§2.2` 的「**安全闸归关**」列**互为镜像**，🔴 **任一侧新增词面，必须在同一次改动里同时标注它归哪一关。**
>
> **两个方向各自会坏成什么样**：
> - **词表侧加词、本表没加** → 那个词只是「文案不许写」，🔴 **生成侧拦不住**。审稿能挡住人写的文案，挡不住模型生成的。
> - **本表加词、词表没标** → 🔴 **写文案的人不知道它已被拦**，会反复提交被拦的稿子，而拦截原因在文案侧的规范里查不到。
>
> 🔴 **不接受「先改一侧、另一侧回头再补」** —— 中间那段时间里两侧就是矛盾的，而矛盾的具体表现正是本节开头那条：**同一词面被两关给出相反判定，先写的那一关赢，行为不可预测**。`S11` 修好了「逝去 / 离世」这一个词面，🔴 **但没有任何机制阻止下一个词面再犯**——`MOD3` 补的就是那个机制。
>
> **加词时必答的三个问题**（答不出就说明还没想清楚，不要先合入）：① 它是**无条件禁**还是**按 `objectStatus` 判定**？② 归**第二关**（产品红线词表）还是**第四关 A / B 组**？③ 命中后**要不要额外记内容侧告警**（A 组要，B 组不要）？

🆕 🔴 **拦截统计口径**（`DECISIONS §G⁗⁗⁗″ S12 ①`）：**`deceased` + B 组不进拦截分母。** 上文规则 2 已写「不得计入拦截率」，此处把它明确到**分母**这一层——🔴 **不许实现成「进分母但判通过」**。那与规则 2 禁止的「命中后豁免」是同一件事的两种写法：功能行为看着一样，但拦截率报表里会出现一批**正常承接**被算作风险样本，下一轮必然有人据此来"收紧"。<br>**QA 判据**：查拦截样本明细，`deceased` 下的 B 组措辞**一条都不该出现在里面**（`§8 TC-SEC-11` 第 ② 项）。

#### 4.3.3 第五关：在世对象不得生成 ta 的口吻

**检查项**（`objectKind=person` 且 `objectStatus ∈ {living, unknown}`）：

| 不得输出 | 具体形态 |
|---|---|
| **ta 的口吻** | 以对象为第一人称自称；「ta 说 / ta 捎来 / ta 的近况 / ta 的来信 / ta 想告诉你」这类框架；任何把内容归属为"对象发出"的呈现 |
| **肖像拟真** | 定妆 / 换装 / 动态化 / 唤醒视频等以该对象形象为素材的拟真生成 |
| **声音克隆** | 以该对象声音为素材的音色复刻与语音合成 |

**可以输出**（不要连这些一起拦）：用户自己的记录、回忆、想说的话与寄托；用户上传的**原始**照片（用户自己的素材，不经拟真加工）；呈现落在"你写给 ta 的"，不落在"ta 捎来的"。

**处置**：
- **文本类**：命中 → 不投递，回落兜底。
- 🔴 **拟真类（肖像 / 声音）在生成前就要拒。** 这两类**不能只靠输出侧**——图像与音频的"越界"无法靠词表判定，且成本已经花掉、素材已经产出，此时才拦等于已经存在一份不该存在的产物。**判定点前移到 §4.1 建档与生成入口**：`person + living`（含 `unknown`）的对象，拟真类生成任务**不予创建**，返回温柔说明而非报错。

**🔴 理由（必须连同结论一起读，否则后人会当成保守而放开）**：

> 逝者场景的授权来自**近亲属**（《民法典》第 994 条：死者肖像、名誉等受保护，维权主体为近亲属，因此"取得近亲属同意"是一条可走通的授权路径）。
> **在世者的肖像与声音属于本人的人格权**（《民法典》第 1018、1019、1023 条），授权主体**只能是本人**。用户 A 上传用户 B 的照片，**A 无权代 B 授权**；平台据此拟真，**没有合法授权基础**。
> 🔴 **这不是"风险偏高"，是无授权可依。** 风险偏高可以靠加水印、加标识、加免责声明来降；无授权可依**加什么都不成立**。

🔴 **放开的前置条件是「取得对象本人可验证同意」的机制落地**，不是"我们觉得可以放开了"。在该机制落地前，任何以"基调已经放宽了"为由要求放开在世者拟真的提案，**引用本条关闭**（同 `COPY-GUIDE §2.7`）。

🟢 **对宠物无影响**：宠物不享有人格权，不存在授权主体问题，**在世宠物照常适用**——宠物近况、回声、定妆一律不受本关约束。它们仍受第四关约束（不得断言已离世）与第二关约束（不得拟真到"它还活着"，CM2）。

**可验证判据**：`person + living` 的对象，请求近况 / 来信一律拿不到 ta 口吻的内容，请求定妆 / 唤醒视频 / 声音克隆一律**建不出任务**；同一批请求把 `objectKind` 换成 `pet` 后**全部正常产出**。判据落用例 **TC-SEC-12**。

### 4.4 广场 / 共鸣厅（公开层入口）

- 分页**硬上限**，`pageSize` 服务端钳制，游标不可被构造成全量拉取（T1）。
- 列表**只出缩略图 + 水印**，不出原图直链（CM-G4）。
- 异常访问模式（高频翻页、顺序遍历、单 IP 大量拉取）触发降速与告警。
- 公开层内容**禁外链、禁联系方式、禁收款码**（T5），文本与图像双通道检查。

### 4.5 窗口页（他人纪念页）——情感攻击靶心

**核心设计决定：公开层互动不开放自由文本。**

献花、记得都是**无文本动作**——这不只是产品调性，更是安全设计：**没有文本输入框，就没有辱骂、没有引流、没有诈骗话术、没有 XSS**。一个决定同时消掉四类风险。

因此：
- 献花/记得/看过 均为无文本动作，**一人一次或按配额**，约束在**后端**（前端 disable 不算数）。
- 举报入口必须常驻可达。
- 窗口主人可**关闭互动**（`SPEC-publish-and-ops`），关闭后所有互动入口对所有人失效。
- 未来若开放评论/留言，**必须先具备**：举报 + 拉黑 + 关闭互动 + 审核队列 + 文本安全闸，五项齐备才可上线。**这是硬前置。**

> 🔄 **2026-08-25 收窄（`DECISIONS S13`，`S5` 就地收窄；🔴 本段上文原文全部保留，一个字未改写）**
>
> **现口径**：`C1 留一句话`（≤60 字，作者三选一处理）**按 `PALETTE §186` P0 清单正常实现**，由**服务端开关**控制，🔴 **P0 默认关闭**；后续开启**不需要重新拍板**。
>
> 🔴 **这是收窄，不是推翻。上面那条「一个决定同时消掉四类风险」的论证一个字都没有被否定** —— 正因为它成立：
> - 开关才 **P0 默认关闭**；
> - 上面最后一条「五项齐备才可上线」的**硬前置照原样保留**，🔴 **并升格为开关的开启条件**：开关**只允许在文本安全闸与 `S3` 五项治理能力（拉黑 / 举报 / 关互动 / 审核队列 / 文本安全闸）全部就绪后**打开。
>
> 变的只有一点：由「**不做这个功能**」改为「**做，但默认关着**」。
>
> 🔴 **开关本身就是一个风险面，必须当作风险面管**：有输入框而无治理能力，等于把风险敞口交给一个配置项 —— **打开它不需要改代码、不需要评审，流水上也看不出异常**。因此已纳入 `SPEC-admin-console §4.7 ②`「四类开关不看比例一律二次审批」清单，🔴 **归「内容可见性」类**。
>
> 📌 **一条指标口径连带（不在本规格范围，指出落点）**：开关关闭期间**深共鸣率须显示「无数据」、不得显示 0**——`R3`/`R4` 是它唯一的数据源。落点 `SPEC-admin-console §2.1.1 ⑤` / `§2.5`。

### 4.6 搜索

- 结果**只出公开可见内容**，私密/挚友内容绝不进索引。
- 不得成为**用户枚举**工具：不支持按精确 id 反查、结果分页有上限、不回显"该用户存在但不可见"这类差异化信息。
- 搜索词与历史存本地，不上报原文（隐私），埋点只报聚合行为。

### 4.7 亲友 / 关系链

- 「不看」三档在**服务端**生效（列表、动态圈、消息全线）。
- **补齐拉黑**：单向、彻底不可见、不可感知（T7）。
- 动态可见性以**内容所有者的授权**为准，不以"是不是亲友"为准。

### 4.8 商店 / 付费

- 价格与商品**以服务端为准**，客户端传来的金额一律不采信。
- 订单**幂等**，防重放与重复扣款。
- 购买回执明确 `affectsUnlock=false`——**任何路径都不能用钱解锁回忆内容**（已定红线，安全上也要防绕过：直接调解锁接口带 paid 参数必须被拒）。

### 4.9 导出（CM-G1）

- 导出是**批量数据出口**，风险等级等同数据库导出：需绑定身份、有频率限制、下载链接签名限时且一次性、任务状态接口做归属校验（防猜 jobId 拿别人的包）。
- 导出行为必须审计留痕。

### 4.10 文件访问 `/files/{key}`

- **当前直出，是明确缺口**（CM-G4）：改为**签名 + 限时**访问。
- key 即便是雪花 ID 也**不可作为唯一凭据**（可枚举）。
- 公开层给缩略图+水印；原图仅本人及授权守护者可取。

### 4.11 WebSocket

- 连接需鉴权，禁止未授权连接与订阅他人频道。
- 单账号/单 IP 连接数上限，防连接耗尽。
- 服务端推送内容遵循与 HTTP **同一套**可见性与最小化规则（不能因为走 WS 就放宽）。

### 4.12 分享落地页 `/w/{windowId}` 与分享预览图 `/share/*`（新增出入口登记）

> 本规格的职责是**逐出入口**。这两个是为补齐站外 AI 标识而新增的**公开、免鉴权**入口（产品规格 `SPEC-trust-and-compliance §CM-G0S S-11`，契约 `API-CONTRACT §16`，部署 `DEPLOY §1.5`），**登记在此**——不登记就没人按本规格的口径审它，而它恰好是风险最高的一类：服务端渲染 + 免登录 + 面向公网爬虫。

**分享落地页 `GET /w/{windowId}`（返回 HTML）**

- 🔴 **可见性与软删过滤在服务端完成**，不得依赖前端。仅 `visibility=public` 且已过审的窗返回 `200`；不存在 / 已软删 / `private` / `friends` / 未过审一律 **`404`**（**不是 410**，对外不暴露"这里曾经有过东西"，与 `SPEC-trust-and-compliance §CM-G0S S-1 ②` 同一口径）。
- 🔴 **`404` 的响应体里不得含任何内容字段**——包括 `og:title` / `og:description` / `og:image`。**meta 标签是最容易漏的泄露面**：正文渲染做了权限判断、`<head>` 却先拼好了，等于把标题和封面直接送出去。
- **不得成为窗口枚举工具**（同 §4.6）：`windowId` 不可作为唯一凭据；对单 IP 的 `404` 率做监控与限流，防遍历探测哪些 id 存在。
- **XSS**：标题 / 描述 / 昵称进 HTML 属性与文本节点均须转义；`og:*` 的 `content` 属性是**服务端拼串**，是本产品第一处真正的服务端模板注入面（此前全站是 SPA，没有这个面）。
- **不做 UA 分流**（详见 `S-11 ②` 第 5 条）：给爬虫和真人返回同一份 HTML。除了避免 cloaking，安全上的收益是**不存在"伪造 UA 拿到另一份内容"这条路径**。
- **光谱数据继续全额禁入**（§1 T6 / §6-5）：分享落地页属"分享路径"，`/spectrum` 的任何字段**不得出现**在 meta 或首屏。

**分享预览图 `POST /share/og-image` 与 `/share/og/*`**

- 🔴 **不是通用出图能力**：只接受**已存在且公开**的 `windowId`，其余 `404`；`title` / `cover` 与库内值不一致时**以库内值为准**。否则它就是一个可以合成任意图文的免费图床，且能被用来**伪造预览图**（让一个链接在微信里显示成任意标题与封面）。
- **限流按 §2.2 三维度同时生效**（账号 / IP / 端点）；合成是 CPU 与带宽密集操作，无限流即 DoS 面。缓存键 `(windowId, aiGenerated, templateVersion)` 同时是天然的限流器——命中缓存不重复合成。
- `/share/og/*` 是**长期公开可读**目录（这是微信抓取的硬要求，见 `DEPLOY §1.5`）。🔴 **该目录只放我方合成的预览图，不得混入用户上传素材**；`/files/{key}` 的签名限时策略（§4.10 / `CM-G4`）**不因本条放宽一分**。
- 🔴 **只读不写用户素材**：合成过程只读封面、只产出一张新图，**绝不回写或覆盖用户原始素材的任何字节**（`TECH-DESIGN §3.12` 红线 `L2`/`L4`）。
- 软删 / 改判后**预览图须在 ≤5 秒内失效**（同 `S-1 ③`）。⚠️ **第三方平台已缓存的旧图无法回收**，属已知不可控残留（`§3.12.4`）——这一点**必须在对外承诺里如实说明，不得写成"分享内容可完全撤回"**。

### S1′ 带来的简化：记得的防刷降级

**绑定墙的统一要求**（产品）：
- 位置：**在用户表达意图之后、投入成本之前**。建档放在 CTA 之后、上传之前；献花/记得放在点击那一下之后立即弹出——**绝不能等用户已经选完照片、写完文字才拦**，那是最伤的时机。
- 措辞：一次说清为什么，落在「为了不弄丢」而不是「我们要查你」。例：「要开始为 ta 建一个地方，先让我们知道你是谁——这样它才不会丢」。
- 方式做到最轻：一键微信 / 手机号验证码，不做冗长注册表单。
- 绑定完成后**原地继续**刚才的动作，不要把用户甩回首页重来。

**绑定墙的位置与措辞**（产品要求）：放在**建档 CTA 之后、上传之前**，一次说清为什么（"要开始为 ta 建一个地方，先让我们知道你是谁——这样它才不会丢"），**不要在用户已经选完照片后才拦**，那是最伤的时机。绑定方式做到最轻（一键微信/手机号）。

## §8 验收（交 QA 细化为 L0 用例）

- **TC-SEC-01** 改 id 访问他人资源（窗口/回声/明信片/亲友/光谱/导出任务）全部被拒。
- **TC-SEC-02** 私密内容对非授权者在**接口层**不可见（不是前端不显示）。
- **TC-SEC-03** 上传伪装文件/SVG/超大文件/带 `../` 文件名 均被拒；上传后 EXIF 已清除。
- **TC-SEC-04** 构造注入型宠物名/故事，AI 输出不越界、不回显指令；越界内容不投递。
- **TC-SEC-05** 脚本刷献花/记得/识别，被限流且提示温柔、不暴露阈值。
- **TC-SEC-06** 大 pageSize / 连续翻页无法批量拉全站；公开层拿不到原图直链。
- **TC-SEC-07** 客户端无法构造系统消息；消息跳转不能跳出白名单；不能标记他人消息已读。
- **TC-SEC-08** 拉黑后对方行为不产生任何消息与可见性，且对方无感知。
- **TC-SEC-09** 篡改金额/商品/重放购买请求均失败；带 paid 的解锁请求被拒。
- **TC-SEC-10** 生产构建中 dev-only 路由不存在；日志与响应无 key、无堆栈、无内部路径。
- 🆕 **TC-SEC-11** 丧失断言闸（§4.3.2）。同一段输入只改 `objectStatus`：
  ① `unknown` 与 `living` 下，A 组与 B 组词面、断言句式**全部不投递**；

  ③ A 组词面在 `deceased` 下**仍不投递**，并落一条内容侧告警；
  ④ 字段缺失 / 传非法值 → 按 `unknown` 判定；
  ⑤ 通用位置（引导语 / 空状态 / 入口文案）携带 `deceased` → 降级按 `unknown` 判定并落调用方违规告警。
